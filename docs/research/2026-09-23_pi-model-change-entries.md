# Research: Pi model and thinking-level session-tree entries

## Scope

This report follows the vendored pi source at `.research/pi/source`. It distinguishes the coding-agent `SessionManager`/`AgentSession` path from the lower-level `packages/agent` harness session types and reducer, since their entry representations and context-building details differ.

## Summary

- Model changes are `model_change` entries (`provider`, `modelId`); thinking changes are `thinking_level_change` entries (`thinkingLevel`). Both are tree children with IDs, parent IDs and timestamps.
- `AgentSession` appends model changes immediately on model selection/cycling, without equality deduplication. Thinking changes are clamped and appended only when the effective level differs. Initial settings are written for new sessions.
- Persisted settings are reconstructed from the active leaf's path, not from all session branches. In-memory model and thinking values live on the Agent state.
- Tree navigation rebuilds messages but does not copy the branch-derived model or thinking level into that live Agent state. Resume does resolve model from the selected path when possible; a CLI model override takes precedence but is not itself appended on an existing session at startup.
- Neither change entry is an LLM message or a chat transcript item. The tree selector hides them by default and in `no-tools`/`user-only`, shows them in `all`, and shows them in `labeled-only` only when labelled.
- Compaction affects message context, not the path scan that derives model/thinking. Branch summaries become context messages but do not set either value.

## Findings

### Entry types, writes, and active runs

The coding-agent session format defines `ModelChangeEntry` with `type: "model_change"`, `provider`, and `modelId`, and `ThinkingLevelChangeEntry` with `type: "thinking_level_change"` and `thinkingLevel`; both inherit `id`, `parentId`, and ISO `timestamp` ([session-manager.ts:49-67](../../../../.research/pi/source/packages/coding-agent/src/core/session-manager.ts#L49-L67); [session-format.md:213-228](../../../../.research/pi/source/packages/coding-agent/docs/session-format.md#L213-L228)). The harness uses the same discriminants and payloads, but its `EntryBase` also has storage-assigned `seq` and numeric timestamp; its thinking interface is named `ThinkingLevelEntry` ([types.ts:15-36](../../../../.research/pi/source/packages/agent/src/harness/session/types.ts#L15-L36)).

`SessionManager.appendModelChange()` and `appendThinkingLevelChange()` each create a fresh ID, parent the entry to the current leaf, append it, and advance the leaf; they do not compare the new value with the prior value ([session-manager.ts:1069-1092](../../../../.research/pi/source/packages/coding-agent/src/core/session-manager.ts#L1069-L1092)). `AgentSession.setModel()` and both model-cycling paths append a model entry on each invocation. They then apply the model's resolved thinking level. `setThinkingLevel()` clamps to the current model's supported levels and appends only when the clamped value differs from the current Agent state ([agent-session.ts:1636-1654](../../../../.research/pi/source/packages/coding-agent/src/core/agent-session.ts#L1636-L1654); [agent-session.ts:1680-1739](../../../../.research/pi/source/packages/coding-agent/src/core/agent-session.ts#L1680-L1739); [agent-session.ts:1754-1773](../../../../.research/pi/source/packages/coding-agent/src/core/agent-session.ts#L1754-L1773)). These writes do not wait for a subsequent user or assistant message.

On a new session, `createAgentSession()` appends the initial model (if present) and thinking level. On an existing session, it appends a thinking entry only if the active branch has no thinking-level entry; it does not append the restored model at startup ([sdk.ts:190-250](../../../../.research/pi/source/packages/coding-agent/src/core/sdk.ts#L190-L250); [sdk.ts:375-385](../../../../.research/pi/source/packages/coding-agent/src/core/sdk.ts#L375-L385)).

Model/thinking setters mutate Agent state immediately; they are not put on the user-message steering/follow-up queues. The Agent captures model/reasoning in its loop config, while `AgentSession`'s `prepareNextTurnWithContext` refreshes those values from live Agent state after each turn. Thus an in-flight provider request keeps its captured configuration; a later assistant request in the same run can use the changed values ([agent.ts:425-480](../../../../.research/pi/source/packages/agent/src/agent.ts#L425-L480); [agent-loop.ts:155-244](../../../../.research/pi/source/packages/agent/src/agent-loop.ts#L155-L244); [agent-session.ts:542-562](../../../../.research/pi/source/packages/coding-agent/src/core/agent-session.ts#L542-L562)). Tree navigation is explicitly rejected while streaming ([agent-session.ts:3072-3074](../../../../.research/pi/source/packages/coding-agent/src/core/agent-session.ts#L3072-L3074)).

### Source of current model/thinking; navigation, forks, and resume

The persisted settings are branch-scoped. `buildSessionPath()` walks from the requested/current leaf to the root and reverses that path; `getSessionContextSettings()` scans it in order, starting with thinking `off` and model `null`. Thinking entries replace the thinking value; model-change entries and assistant messages replace the model value, with the latest such entry on the path winning ([session-manager.ts:334-376](../../../../.research/pi/source/packages/coding-agent/src/core/session-manager.ts#L334-L376)). The harness context builder likewise scans path entries and returns model/thinking alongside, but separately from, messages ([context.ts:25-42](../../../../.research/pi/source/packages/agent/src/harness/session/context.ts#L25-L42)). The harness reducer starts with its supplied defaults and replays branch configuration entries and operation-owned entries in sequence order; model changes, thinking changes, and assistant-message metadata update the effective configuration ([reducer.ts:113-118](../../../../.research/pi/source/packages/agent/src/harness/reducer.ts#L113-L118); [reducer.ts:400-423](../../../../.research/pi/source/packages/agent/src/harness/reducer.ts#L400-L423)).

At runtime, however, `AgentSession.model` and `.thinkingLevel` read the live Agent state ([agent-session.ts:888-896](../../../../.research/pi/source/packages/coding-agent/src/core/agent-session.ts#L888-L896)). `navigateTree()` changes the session leaf and rebuilds the Agent's messages from the new path, but assigns only `agent.state.messages`; it does not assign the branch-derived model or thinking level ([agent-session.ts:3204-3242](../../../../.research/pi/source/packages/coding-agent/src/core/agent-session.ts#L3204-L3242)). So navigation does not restore those two values in the already-running session object.

`createBranchedSession(leafId)` writes only the selected root-to-leaf path to a new session file; `forkFrom()` instead copies all non-header entries from its source file and adds a parent-session reference ([session-manager.ts:1413-1455](../../../../.research/pi/source/packages/coding-agent/src/core/session-manager.ts#L1413-L1455); [session-manager.ts:1576-1627](../../../../.research/pi/source/packages/coding-agent/src/core/session-manager.ts#L1576-L1627)). On opening a file, `SessionManager` assigns its leaf while loading each entry, leaving the last serialized entry as leaf ([session-manager.ts:959-968](../../../../.research/pi/source/packages/coding-agent/src/core/session-manager.ts#L959-L968)). Resume then derives settings from that leaf's path.

During resume, a model derived from the active path is restored only if the runtime can resolve it and the provider has configured authentication. Otherwise the SDK records a fallback message and calls `findInitialModel()`, which tries the saved global default with configured auth, then available models, or returns no model ([sdk.ts:198-229](../../../../.research/pi/source/packages/coding-agent/src/core/sdk.ts#L198-L229); [model-resolver.ts:674-708](../../../../.research/pi/source/packages/coding-agent/src/core/model-resolver.ts#L674-L708)). The separate `restoreModelFromSession()` helper describes the same missing-model/no-auth fallback cases ([model-resolver.ts:720-778](../../../../.research/pi/source/packages/coding-agent/src/core/model-resolver.ts#L720-L778)).

### LLM context and UI rendering

Change entries are not converted into `AgentMessage`s: `sessionEntryToContextMessages()` handles messages, custom messages, branch summaries and compactions, then returns an empty list for other entry types ([session-manager.ts:383-411](../../../../.research/pi/source/packages/coding-agent/src/core/session-manager.ts#L383-L411)). The harness projector has the same fall-through for model/thinking entries ([context.ts:53-80](../../../../.research/pi/source/packages/agent/src/harness/session/context.ts#L53-L80)). Their effect is runtime configuration, not text in the prompt.

The interactive chat renderer maps session entries through that projector; model/thinking entries therefore produce no chat component or historical text ([interactive-mode.ts:3778-3792](../../../../.research/pi/source/packages/coding-agent/src/modes/interactive/interactive-mode.ts#L3778-L3792)). The tree selector renders them as dim text, `[model: <modelId>]` and `[thinking: <level>]` ([tree-selector.ts:830-835](../../../../.research/pi/source/packages/coding-agent/src/modes/interactive/components/tree-selector.ts#L830-L835)). Its `default` and `no-tools` modes classify both as settings entries and hide them; `user-only` admits only user-message entries; `all` admits every entry; `labeled-only` admits only entries with a label ([tree-selector.ts:94-95](../../../../.research/pi/source/packages/coding-agent/src/modes/interactive/components/tree-selector.ts#L94-L95); [tree-selector.ts:355-383](../../../../.research/pi/source/packages/coding-agent/src/modes/interactive/components/tree-selector.ts#L355-L383)).

### Compaction and branch summaries

Coding-agent `buildSessionContext()` derives model/thinking from the full leaf-to-root path, separately from the compaction-aware message entries. Its compaction transform retains the compaction and selected kept entries plus later entries; omitted earlier messages do not remove path settings from the settings scan ([session-manager.ts:418-469](../../../../.research/pi/source/packages/coding-agent/src/core/session-manager.ts#L418-L469)). The harness similarly derives settings before applying context-entry transforms; a compaction projects to a summary plus its `retainedTail` messages ([context.ts:25-42](../../../../.research/pi/source/packages/agent/src/harness/session/context.ts#L25-L42); [context.ts:45-80](../../../../.research/pi/source/packages/agent/src/harness/session/context.ts#L45-L80)).

A branch summary is projected as a context message, but neither the context projector nor settings derivation treats it as a model/thinking change ([session-manager.ts:383-411](../../../../.research/pi/source/packages/coding-agent/src/core/session-manager.ts#L383-L411); [context.ts:53-80](../../../../.research/pi/source/packages/agent/src/harness/session/context.ts#L53-L80)). When navigation creates one, it is appended at the new target leaf; the derived settings therefore come from that target path, not from the abandoned path ([agent-session.ts:3204-3242](../../../../.research/pi/source/packages/coding-agent/src/core/agent-session.ts#L3204-L3242)). The session-format document distinguishes coding-agent compactions with `firstKeptEntryId` from newer harness compactions with `retainedTail` ([session-format.md:234-248](../../../../.research/pi/source/packages/coding-agent/docs/session-format.md#L234-L248)).

### Defaults and CLI overrides

A valid model found on the active session path takes precedence over a changed global default at resume. If path restoration fails, the SDK falls back to the configured global model and then available models ([sdk.ts:198-229](../../../../.research/pi/source/packages/coding-agent/src/core/sdk.ts#L198-L229); [model-resolver.ts:674-708](../../../../.research/pi/source/packages/coding-agent/src/core/model-resolver.ts#L674-L708)). Thinking restoration uses an active-branch thinking entry when one exists; otherwise it uses the current global thinking default or the built-in default. The selected level is then clamped to the selected model's capabilities ([sdk.ts:227-250](../../../../.research/pi/source/packages/coding-agent/src/core/sdk.ts#L227-L250)). When switching models, a scoped explicit level takes priority, then a per-model thinking override, then the global thinking default/current level/default; `persist` writes global model or thinking defaults separately from session entries ([agent-session.ts:1630-1654](../../../../.research/pi/source/packages/coding-agent/src/core/agent-session.ts#L1630-L1654); [agent-session.ts:1808-1826](../../../../.research/pi/source/packages/coding-agent/src/core/agent-session.ts#L1808-L1826); [settings-manager.ts:717-739](../../../../.research/pi/source/packages/coding-agent/src/core/settings-manager.ts#L717-L739)).

CLI `--model` resolution sets the initial `options.model`, which takes precedence over session restoration. For an existing session, SDK startup does not append a `model_change` for that override; the assistant message from a later response carries its actual provider/model and is used by future path derivation. For a new session, the initial model is appended. For explicit CLI `--thinking` or `--model ...:<thinking>`, startup initialises the Agent to the clamped CLI level and `main.ts` calls `setThinkingLevel()`. If the existing branch already has a thinking entry, this setter sees no state change and appends nothing; if it has no thinking entry, SDK initialisation appends the current level, including the CLI value. New sessions append their initial thinking level ([main.ts:457-482](../../../../.research/pi/source/packages/coding-agent/src/main.ts#L457-L482); [main.ts:827-830](../../../../.research/pi/source/packages/coding-agent/src/main.ts#L827-L830); [sdk.ts:375-385](../../../../.research/pi/source/packages/coding-agent/src/core/sdk.ts#L375-L385)).
