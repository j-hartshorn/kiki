# Research: Agent tool sets and arena execution

## Scope

This document compares the default coding-agent tool surfaces and tool-call execution paths in Maki, Pi, OpenAI Codex, and Hugging Face smolagents, then traces Kiki's current code-arena-to-Rust path through Monty 0.0.21. It covers tool definition, model exposure, dispatch, result ordering, async host functions, batching, and concurrency.

The reference snapshots are Maki [`e0d87e35`](../../.research/maki/README.md), Pi [`587be985`](../../.research/pi/pi-agentic-harness.md#scope), a one-commit shallow checkout of Codex at `2b7c279735d0d096cf7b34fe98938f46792f4d4f`, and a one-commit shallow checkout of smolagents at `30bb1161095dbae2271e6bc3cc4c219cc3897a57`. This document does not select Kiki's future default tools or specify implementation changes.

## Summary

- Pi has the narrowest ordinary coding surface: `read`, `bash`, `edit`, and `write`; its separate read-only set is `read`, `grep`, `find`, and `ls` ([`index.ts:158`](../../.research/pi/source/packages/coding-agent/src/core/tools/index.ts#L158), [`index.ts:195`](../../.research/pi/source/packages/coding-agent/src/core/tools/index.ts#L195)).
- Maki enables 19 bundled plugins; 18 register primary model tools, `sessions` registers commands instead, and the `edit` plugin enables `multiedit` by default ([`lib.rs:58`](../../.research/maki/source/maki-config/src/lib.rs#L58), [`sessions/init.lua:565`](../../.research/maki/source/plugins/sessions/init.lua#L565), [`edit/init.lua:237`](../../.research/maki/source/plugins/edit/init.lua#L237)).
- Codex's surface is assembled per turn rather than represented by one fixed list. An ordinary environment can contribute resumable shell tools, model-dependent `apply_patch`, `view_image`, `request_user_input`, and collaboration tools; MCP, plan, code-mode, clock, permission, and search tools are conditional ([`spec_plan.rs:972`](../../.research/codex/source/codex-rs/core/src/tools/spec_plan.rs#L972), [`spec_plan.rs:1074`](../../.research/codex/source/codex-rs/core/src/tools/spec_plan.rs#L1074), [`spec_plan.rs:1130`](../../.research/codex/source/codex-rs/core/src/tools/spec_plan.rs#L1130)).
- Smolagents' `CodeAgent` always receives `final_answer` plus caller-supplied tools, optionally adds web search and page visiting, and exposes tools as Python signatures and docstrings in the prompt. Its code path calls tools synchronously and does not support `await`; only the separate `ToolCallingAgent` parallelises a multi-call model response ([`agents.py:394`](../../.research/smolagents/source/src/smolagents/agents.py#L394), [`tools.py:254`](../../.research/smolagents/source/src/smolagents/tools.py#L254), [`local_python_executor.py:1417`](../../.research/smolagents/source/src/smolagents/local_python_executor.py#L1417), [`agents.py:1417`](../../.research/smolagents/source/src/smolagents/agents.py#L1417)).
- Maki, Pi, and Codex separate a model-visible specification from executable runtime behaviour, execute independent calls asynchronously, and publish tool results in model call order ([Maki `registry.rs:193`](../../.research/maki/source/maki-agent/src/tools/registry.rs#L193), [Pi `types.ts:451`](../../.research/pi/source/packages/coding-agent/src/core/extensions/types.ts#L451), [Codex `tool_executor.rs:51`](../../.research/codex/source/codex-rs/tools/src/tool_executor.rs#L51)). Smolagents also separates tool metadata from execution but keeps code-agent tool calls synchronous ([`tools.py:106`](../../.research/smolagents/source/src/smolagents/tools.py#L106), [`local_python_executor.py:825`](../../.research/smolagents/source/src/smolagents/local_python_executor.py#L825)).
- Maki is the direct reference for Kiki's code-arena shape: tools appear as async Python functions, its prompt says every call must be awaited and independent calls must use `gather`, Monty passes a batch of pending calls to the host, and Lua starts that batch concurrently ([`code_execution/init.lua:113`](../../.research/maki/source/plugins/code_execution/init.lua#L113), [`runner.rs:126`](../../.research/maki/source/maki-interpreter/src/runner.rs#L126), [`interpreter.rs:163`](../../.research/maki/source/maki-lua/src/api/interpreter.rs#L163)).
- Kiki currently exposes `read` as an async Python function and tells the model to await it, but it accepts exactly one pending Monty future, awaits that read before resuming Monty, has no gather guidance, and has no concurrent Rust batch execution ([`arena.rs:765`](../../src/arena.rs#L765), [`arena.rs:795`](../../src/arena.rs#L795), [`arena.rs:820`](../../src/arena.rs#L820), [`read_only_agent.md:5`](../../prompts/read_only_agent.md#L5)).
- Monty 0.0.21 itself supports `asyncio.gather`, multiple pending external call IDs, and resolving some or all pending futures; the missing batching is in Kiki's driver rather than the interpreter protocol ([Monty `checkout.rs:142`](https://github.com/pydantic/monty/blob/70fe3f5781381eb33579e45046f8cb3845953373/crates/monty-pool/src/checkout.rs#L142-L170), [`checkout.rs:571`](https://github.com/pydantic/monty/blob/70fe3f5781381eb33579e45046f8cb3845953373/crates/monty-pool/src/checkout.rs#L571-L605), [`asyncio.rs:14`](https://github.com/pydantic/monty/blob/70fe3f5781381eb33579e45046f8cb3845953373/crates/monty/tests/asyncio.rs#L14-L40)).

## Findings

### 1. Default tool surfaces

#### Maki

Maki's configuration enables these bundled plugins by default: `bash`, `batch`, `code_execution`, `edit`, `glob`, `grep`, `index`, `list`, `memory`, `question`, `read`, `sessions`, `skill`, `task`, `todo_write`, `view_image`, `webfetch`, `websearch`, and `write` ([`maki-config/src/lib.rs:58`](../../.research/maki/source/maki-config/src/lib.rs#L58)). `sessions` contributes `/sessions` and `/rename` commands rather than a model tool ([`plugins/sessions/init.lua:565`](../../.research/maki/source/plugins/sessions/init.lua#L565)). The `edit` plugin always registers `edit`, enables `multiedit` by default, and leaves `edit_lines` and `insert_lines` disabled by default ([`plugins/edit/init.lua:237`](../../.research/maki/source/plugins/edit/init.lua#L237), [`plugins/edit/init.lua:248`](../../.research/maki/source/plugins/edit/init.lua#L248), [`plugins/edit/init.lua:299`](../../.research/maki/source/plugins/edit/init.lua#L299)).

The resulting default primary model tools group as follows:

- Files and code inspection: [`read`](../../.research/maki/source/plugins/read/init.lua#L162), [`list`](../../.research/maki/source/plugins/list/init.lua#L16), [`glob`](../../.research/maki/source/plugins/glob/init.lua#L17), [`grep`](../../.research/maki/source/plugins/grep/init.lua#L196), [`index`](../../.research/maki/source/plugins/index/init.lua#L154), and [`view_image`](../../.research/maki/source/plugins/view_image/init.lua#L117).
- Execution and mutation: [`bash`](../../.research/maki/source/plugins/bash/init.lua#L261), [`edit`](../../.research/maki/source/plugins/edit/init.lua#L248), [`multiedit`](../../.research/maki/source/plugins/edit/init.lua#L299), and [`write`](../../.research/maki/source/plugins/write/init.lua#L27).
- Orchestration: [`batch`](../../.research/maki/source/plugins/batch/init.lua#L582), [`code_execution`](../../.research/maki/source/plugins/code_execution/init.lua#L357), and [`task`](../../.research/maki/source/plugins/task/init.lua#L254).
- Agent/session context: [`memory`](../../.research/maki/source/plugins/memory/init.lua#L170), [`question`](../../.research/maki/source/plugins/question/init.lua#L36), [`skill`](../../.research/maki/source/plugins/skill/init.lua#L136), and [`todo_write`](../../.research/maki/source/plugins/todo_write/init.lua#L108).
- Network access: [`webfetch`](../../.research/maki/source/plugins/webfetch/init.lua#L80) and [`websearch`](../../.research/maki/source/plugins/websearch/init.lua#L23).

Audience flags and runtime filters can narrow that surface for the main agent, research/general subagents, the Python interpreter, workflows, disabled tools, and model capabilities ([`registry.rs:21`](../../.research/maki/source/maki-agent/src/tools/registry.rs#L21), [`tools/mod.rs:45`](../../.research/maki/source/maki-agent/src/tools/mod.rs#L45)).

#### Pi

Pi defines eight built-ins: `read`, `bash`, `powershell`, `edit`, `write`, `grep`, `find`, and `ls` ([`index.ts:182`](../../.research/pi/source/packages/coding-agent/src/core/tools/index.ts#L182)). Its ordinary default coding set selects only `read`, `bash`, `edit`, and `write`; its read-only factory instead selects `read`, `grep`, `find`, and `ls` ([`index.ts:158`](../../.research/pi/source/packages/coding-agent/src/core/tools/index.ts#L158), [`index.ts:195`](../../.research/pi/source/packages/coding-agent/src/core/tools/index.ts#L195)).

The implementations are TypeScript tool factories with replaceable operation interfaces: `read` handles text slices and images, `bash` owns process execution and streamed output, `edit` performs exact replacements and diffs, `write` creates/replaces whole files, `grep` uses in-memory matching or `rg`, `find` uses `fd`, and `ls` reads directory entries ([`read.ts:33`](../../.research/pi/source/packages/coding-agent/src/core/tools/read.ts#L33), [`bash.ts:54`](../../.research/pi/source/packages/coding-agent/src/core/tools/bash.ts#L54), [`edit.ts:48`](../../.research/pi/source/packages/coding-agent/src/core/tools/edit.ts#L48), [`write.ts:20`](../../.research/pi/source/packages/coding-agent/src/core/tools/write.ts#L20), [`grep.ts:37`](../../.research/pi/source/packages/coding-agent/src/core/tools/grep.ts#L37), [`find.ts:35`](../../.research/pi/source/packages/coding-agent/src/core/tools/find.ts#L35), [`ls.ts:26`](../../.research/pi/source/packages/coding-agent/src/core/tools/ls.ts#L26)).

#### Codex

Codex constructs a registry from the current turn's environment, model metadata, feature configuration, MCP state, session source, and multi-agent mode ([`spec_plan.rs:972`](../../.research/codex/source/codex-rs/core/src/tools/spec_plan.rs#L972)). Its stable default features include shell, unified exec, view image, and collaboration ([`features/src/lib.rs:879`](../../.research/codex/source/codex-rs/features/src/lib.rs#L879), [`features/src/lib.rs:903`](../../.research/codex/source/codex-rs/features/src/lib.rs#L903), [`features/src/lib.rs:1205`](../../.research/codex/source/codex-rs/features/src/lib.rs#L1205)).

For an ordinary turn with an available execution environment:

- Shell assembly adds `exec_command` and `write_stdin` when unified exec is enabled; managed configurations can fall back to one-shot `exec_command` ([`spec_plan.rs:1074`](../../.research/codex/source/codex-rs/core/src/tools/spec_plan.rs#L1074)).
- `apply_patch` is added only when the model metadata declares an apply-patch tool type ([`spec_plan.rs:1232`](../../.research/codex/source/codex-rs/core/src/tools/spec_plan.rs#L1232)).
- `view_image` is added when its feature is enabled ([`spec_plan.rs:1246`](../../.research/codex/source/codex-rs/core/src/tools/spec_plan.rs#L1246)).
- `request_user_input` is enabled unless explicitly disabled and is exposed only as a direct model tool ([`config/mod.rs:2631`](../../.research/codex/source/codex-rs/core/src/config/mod.rs#L2631), [`spec_plan.rs:1152`](../../.research/codex/source/codex-rs/core/src/tools/spec_plan.rs#L1152)).
- Collaboration V1 is selected from the stable default feature unless configuration or model metadata overrides it; collaboration registration is also constrained by agent depth and session source ([`config/mod.rs:1539`](../../.research/codex/source/codex-rs/core/src/config/mod.rs#L1539), [`spec_plan.rs:647`](../../.research/codex/source/codex-rs/core/src/tools/spec_plan.rs#L647), [`spec_plan.rs:1260`](../../.research/codex/source/codex-rs/core/src/tools/spec_plan.rs#L1260)).

`update_plan` is opt-in, MCP resource tools require connected servers, and permission, token-budget, clock, sleep, deferred-executor, code-mode, and tool-search surfaces depend on their associated features or runtime state ([`config/mod.rs:2639`](../../.research/codex/source/codex-rs/core/src/config/mod.rs#L2639), [`spec_plan.rs:1121`](../../.research/codex/source/codex-rs/core/src/tools/spec_plan.rs#L1121), [`spec_plan.rs:1136`](../../.research/codex/source/codex-rs/core/src/tools/spec_plan.rs#L1136), [`spec_plan.rs:1178`](../../.research/codex/source/codex-rs/core/src/tools/spec_plan.rs#L1178)).

#### Smolagents

Smolagents does not ship a fixed coding tool set. Every agent receives caller-supplied tools and an automatically inserted `final_answer`; `add_base_tools=True` additionally inserts DuckDuckGo search and page visiting, while its Python-interpreter tool is reserved for `ToolCallingAgent` because `CodeAgent` already executes Python ([`agents.py:394`](../../.research/smolagents/source/src/smolagents/agents.py#L394), [`default_tools.py:678`](../../.research/smolagents/source/src/smolagents/default_tools.py#L678)). `CodeAgent` also exposes an allow-list of ordinary Python built-ins independently of model-facing tools ([`local_python_executor.py:73`](../../.research/smolagents/source/src/smolagents/local_python_executor.py#L73), [`local_python_executor.py:1738`](../../.research/smolagents/source/src/smolagents/local_python_executor.py#L1738)).

Caller-defined tools subclass `Tool` or use the `@tool` decorator; names, descriptions, input schemas, output types, type hints, and docstrings form their interface ([`tools.py:106`](../../.research/smolagents/source/src/smolagents/tools.py#L106), [`tools.py:1061`](../../.research/smolagents/source/src/smolagents/tools.py#L1061)). A tool may declare a structured output schema, in which case its code prompt explicitly tells the model to access returned dictionary fields directly rather than printing and reparsing the value ([`tools.py:254`](../../.research/smolagents/source/src/smolagents/tools.py#L254)).

### 2. Definition, registration, and model exposure

#### Maki: Lua definitions behind Rust traits

Lua plugins call `maki.api.register_tool` with name, description, schema, handler, audience, permission, display, and timeout data; the host converts those registrations into implementations of Rust's `Tool` and `ToolInvocation` traits ([`api/tool.rs:1243`](../../.research/maki/source/maki-lua/src/api/tool.rs#L1243), [`registry.rs:193`](../../.research/maki/source/maki-agent/src/tools/registry.rs#L193)). `ToolRegistry` stores an atomically replaceable snapshot, and rebuilds filtered model definitions on every request so runtime registrations appear on the next turn ([`registry.rs:250`](../../.research/maki/source/maki-agent/src/tools/registry.rs#L250), [`registry.rs:420`](../../.research/maki/source/maki-agent/src/tools/registry.rs#L420)).

#### Pi: one extension-facing definition type

Pi's `ToolDefinition` combines the model name, description, TypeBox schema, optional prompt contribution, execution mode, async executor, and TUI renderers ([`extensions/types.ts:451`](../../.research/pi/source/packages/coding-agent/src/core/extensions/types.ts#L451)). The session builds all built-in definitions, merges extension and SDK tools, applies active-name filters, and wraps definitions for the provider-neutral agent loop ([`agent-session.ts:2725`](../../.research/pi/source/packages/coding-agent/src/core/agent-session.ts#L2725)). The default prompt derives its `Available tools` and guidelines sections from active definitions' prompt contributions ([`system-prompt.ts:94`](../../.research/pi/source/packages/coding-agent/src/core/system-prompt.ts#L94), [`system-prompt.ts:115`](../../.research/pi/source/packages/coding-agent/src/core/system-prompt.ts#L115), [`system-prompt.ts:130`](../../.research/pi/source/packages/coding-agent/src/core/system-prompt.ts#L130)).

#### Codex: per-turn specs tied to executors

Codex's `ToolExecutor` contract ties a `ToolSpec`, exposure policy, parallelism declaration, and async handler to each runtime tool ([`tool_executor.rs:51`](../../.research/codex/source/codex-rs/tools/src/tool_executor.rs#L51), [`tool_executor.rs:106`](../../.research/codex/source/codex-rs/tools/src/tool_executor.rs#L106)). Exposure can be direct, deferred/searchable, direct-model-only, code-mode-only, or hidden ([`tool_executor.rs:51`](../../.research/codex/source/codex-rs/tools/src/tool_executor.rs#L51)). The per-turn plan merges core, MCP, and extension sources, resolves namespaces and collisions, then projects only direct entries into the model-visible specification ([`spec_plan.rs:125`](../../.research/codex/source/codex-rs/core/src/tools/spec_plan.rs#L125), [`spec_plan.rs:356`](../../.research/codex/source/codex-rs/core/src/tools/spec_plan.rs#L356), [`spec_plan.rs:525`](../../.research/codex/source/codex-rs/core/src/tools/spec_plan.rs#L525)).

#### Smolagents: prompt-visible Python interfaces

`CodeAgent` renders each tool through `to_code_prompt`, producing a Python function signature, return type, docstring, argument descriptions, and optional structured-output schema ([`tools.py:254`](../../.research/smolagents/source/src/smolagents/tools.py#L254)). The Jinja prompt inserts those definitions into the model's initial instructions and explicitly states that Python state persists between code executions ([`code_agent.yaml:132`](../../.research/smolagents/source/src/smolagents/prompts/code_agent.yaml#L132), [`code_agent.yaml:167`](../../.research/smolagents/source/src/smolagents/prompts/code_agent.yaml#L167)). The executor receives the corresponding callable objects separately and resolves an AST function call against persistent state, static tools, or custom tools ([`local_python_executor.py:825`](../../.research/smolagents/source/src/smolagents/local_python_executor.py#L825), [`local_python_executor.py:1729`](../../.research/smolagents/source/src/smolagents/local_python_executor.py#L1729)).

### 3. Direct tool-call concurrency and result ordering

Maki collects every tool use from one assistant message, starts each runnable call as a `smol` task, then awaits its task vector in source order and submits one combined result message ([`tool_dispatch.rs:383`](../../.research/maki/source/maki-agent/src/agent/tool_dispatch.rs#L383), [`tool_dispatch.rs:422`](../../.research/maki/source/maki-agent/src/agent/tool_dispatch.rs#L422), [`task_set.rs:13`](../../.research/maki/source/maki-agent/src/task_set.rs#L13)). Each task also catches panics and converts them to tool errors ([`task_set.rs:20`](../../.research/maki/source/maki-agent/src/task_set.rs#L20)).

Pi selects sequential execution when configured globally or when any call in the batch declares `executionMode: "sequential"`; otherwise it starts the prepared call promises under `Promise.all` ([`agent-loop.ts:411`](../../.research/pi/source/packages/agent/src/agent-loop.ts#L411), [`agent-loop.ts:489`](../../.research/pi/source/packages/agent/src/agent-loop.ts#L489), [`agent-loop.ts:540`](../../.research/pi/source/packages/agent/src/agent-loop.ts#L540)). Completion events can occur in completion order, while the resulting messages follow the original call order returned by `Promise.all` ([`agent-loop.ts:526`](../../.research/pi/source/packages/agent/src/agent-loop.ts#L526), [`agent-loop.ts:543`](../../.research/pi/source/packages/agent/src/agent-loop.ts#L543)). Concurrent edits and writes to the same canonical file are serialised by a per-file mutation queue; different files remain independent ([`file-mutation-queue.ts:29`](../../.research/pi/source/packages/coding-agent/src/core/tools/file-mutation-queue.ts#L29)).

Codex starts handling function-call output items while the model stream is still being consumed and stores their futures in a `FuturesOrdered` queue ([`stream_events_utils.rs:318`](../../.research/codex/source/codex-rs/core/src/stream_events_utils.rs#L318), [`turn.rs:2251`](../../.research/codex/source/codex-rs/core/src/session/turn.rs#L2251), [`turn.rs:2422`](../../.research/codex/source/codex-rs/core/src/session/turn.rs#L2422)). A shared async read/write lock admits tools declaring parallel support under read guards and serial tools under a write guard, so a serial tool excludes every other tool while it runs ([`parallel.rs:116`](../../.research/codex/source/codex-rs/core/src/tools/parallel.rs#L116), [`parallel.rs:154`](../../.research/codex/source/codex-rs/core/src/tools/parallel.rs#L154)). The turn drains `FuturesOrdered` into conversation history in model emission order ([`turn.rs:2158`](../../.research/codex/source/codex-rs/core/src/session/turn.rs#L2158), [`turn.rs:2779`](../../.research/codex/source/codex-rs/core/src/session/turn.rs#L2779)).

Smolagents' direct `ToolCallingAgent` path uses a thread pool when one model step contains multiple calls, yields completions as futures finish, then sorts calls and observations by call ID ([`agents.py:1417`](../../.research/smolagents/source/src/smolagents/agents.py#L1417)). This concurrency is not used by `CodeAgent`; its AST evaluator invokes the selected callable synchronously and returns its value inline ([`local_python_executor.py:825`](../../.research/smolagents/source/src/smolagents/local_python_executor.py#L825), [`local_python_executor.py:915`](../../.research/smolagents/source/src/smolagents/local_python_executor.py#L915)).

### 4. Code-arena tool execution in Maki

Maki's `code_execution` description tells the model that all injected tools are async, every call must be awaited, and independent calls should be passed directly to `gather` ([`code_execution/init.lua:113`](../../.research/maki/source/plugins/code_execution/init.lua#L113), [`code_execution/init.lua:130`](../../.research/maki/source/plugins/code_execution/init.lua#L130)). Its preamble supplies a `gather` helper and examples include a dynamically constructed set of concurrent reads ([`code_execution/init.lua:40`](../../.research/maki/source/plugins/code_execution/init.lua#L40), [`code_execution/init.lua:141`](../../.research/maki/source/plugins/code_execution/init.lua#L141)).

The Monty runner records each external `FunctionCall` as a `PendingCall` and resumes it as pending rather than executing it immediately ([`runner.rs:126`](../../.research/maki/source/maki-interpreter/src/runner.rs#L126), [`runner.rs:145`](../../.research/maki/source/maki-interpreter/src/runner.rs#L145)). When Monty emits `ResolveFutures`, the runner collects all requested call IDs into one batch, passes that batch to its resolver, maps results back to IDs, and resumes Monty with the result vector ([`runner.rs:205`](../../.research/maki/source/maki-interpreter/src/runner.rs#L205)). The Lua-side bridge maps the batch to futures and awaits `join_all`, so all handlers are started before their ordered results are returned to Rust ([`api/interpreter.rs:163`](../../.research/maki/source/maki-lua/src/api/interpreter.rs#L163), [`api/interpreter.rs:175`](../../.research/maki/source/maki-lua/src/api/interpreter.rs#L175)).

### 5. Code-agent execution in smolagents

Smolagents' `CodeAgent` and Kiki share code-first composition and persistent Python state, but their host-call semantics differ. Smolagents executes a model-authored block in a local AST evaluator or a remote Python executor, injects synchronous tool callables into that executor, and retains state across blocks ([`agents.py:1505`](../../.research/smolagents/source/src/smolagents/agents.py#L1505), [`local_python_executor.py:1688`](../../.research/smolagents/source/src/smolagents/local_python_executor.py#L1688), [`local_python_executor.py:1729`](../../.research/smolagents/source/src/smolagents/local_python_executor.py#L1729)). The local evaluator supports ordinary function definitions and calls but rejects unhandled AST nodes, which includes `Await` and `AsyncFunctionDef`; it therefore has no code-level gather path for concurrent tool calls ([`local_python_executor.py:1417`](../../.research/smolagents/source/src/smolagents/local_python_executor.py#L1417), [`local_python_executor.py:1493`](../../.research/smolagents/source/src/smolagents/local_python_executor.py#L1493), [`local_python_executor.py:1566`](../../.research/smolagents/source/src/smolagents/local_python_executor.py#L1566)).

Native Python tool return values remain typed and available to later statements in the same code block; only the execution observation sent back through the ReAct loop is converted to bounded text ([`agents.py:1757`](../../.research/smolagents/source/src/smolagents/agents.py#L1757), [`agents.py:1770`](../../.research/smolagents/source/src/smolagents/agents.py#L1770)). The local executor explicitly states that it is not a security sandbox, while remote executors move code and serialised tools into Docker or hosted environments ([`local_python_executor.py:1688`](../../.research/smolagents/source/src/smolagents/local_python_executor.py#L1688), [`remote_executors.py:53`](../../.research/smolagents/source/src/smolagents/remote_executors.py#L53), [`remote_executors.py:107`](../../.research/smolagents/source/src/smolagents/remote_executors.py#L107)).

### 6. Kiki's current arena path

Kiki gives the model one outer provider tool, `execute_python`, and sets OpenAI's direct `parallel_tool_calls` field to `false` ([`openai.rs:135`](../../src/openai.rs#L135), [`openai.rs:142`](../../src/openai.rs#L142)). This controls concurrent outer Responses API tool calls; the nested Python-to-Rust host calls are driven separately in `arena.rs`.

Inside the arena, an undefined-name lookup for `read` returns a Monty function object ([`arena.rs:863`](../../src/arena.rs#L863)). When Python calls it with one string argument, Kiki replies with `ResumeValue::Future`, which makes the function asynchronous from Python's perspective ([`arena.rs:765`](../../src/arena.rs#L765), [`arena.rs:795`](../../src/arena.rs#L795)). `ReadTool::read` is itself async and moves capability-scoped blocking filesystem work to `spawn_blocking` ([`tools.rs:156`](../../src/tools.rs#L156), [`tools.rs:166`](../../src/tools.rs#L166)).

The driver then requires Monty to return `ResolveFutures` immediately with exactly the one current call ID ([`arena.rs:797`](../../src/arena.rs#L797)). It awaits that read inline, converts the result, and resumes Monty with a one-element result vector ([`arena.rs:820`](../../src/arena.rs#L820), [`arena.rs:838`](../../src/arena.rs#L838)). Any other `ResolveFutures` state is a fatal unsupported suspension, and interrupted-read state asserts that only one read can be pending ([`arena.rs:889`](../../src/arena.rs#L889), [`arena.rs:265`](../../src/arena.rs#L265)).

This gives the requested properties the following current status:

|---|---|---|

Monty 0.0.21's protocol is broader than Kiki's current driver. `TurnEvent::ResolveFutures` carries a vector of pending IDs; `ResumeValue::Future` explicitly registers work to resolve later; and `Checkout::resume_futures` accepts results for some or all pending IDs ([Monty `checkout.rs:142`](https://github.com/pydantic/monty/blob/70fe3f5781381eb33579e45046f8cb3845953373/crates/monty-pool/src/checkout.rs#L142-L188), [`checkout.rs:571`](https://github.com/pydantic/monty/blob/70fe3f5781381eb33579e45046f8cb3845953373/crates/monty-pool/src/checkout.rs#L571-L605)). Monty's own gather tests drive multiple `FunctionCall` events to pending state before receiving one `ResolveFutures` containing all pending IDs ([Monty `asyncio.rs:55`](https://github.com/pydantic/monty/blob/70fe3f5781381eb33579e45046f8cb3845953373/crates/monty/tests/asyncio.rs#L55-L84), [`asyncio.rs:717`](https://github.com/pydantic/monty/blob/70fe3f5781381eb33579e45046f8cb3845953373/crates/monty/tests/asyncio.rs#L717-L744)).

### 7. Error and cancellation boundaries

Maki wraps parallel direct calls in a panic-catching task set and converts malformed/failed calls into model-visible tool results; its code-execution bridge associates each nested result or error with the Monty call ID ([`task_set.rs:20`](../../.research/maki/source/maki-agent/src/task_set.rs#L20), [`api/interpreter.rs:163`](../../.research/maki/source/maki-lua/src/api/interpreter.rs#L163)). Pi catches executor exceptions as error tool results and supplies the same abort signal to each call ([`agent-loop.ts:628`](../../.research/pi/source/packages/agent/src/agent-loop.ts#L628)). Codex distinguishes errors that become model output from fatal turn failures and aborts dispatched work through cancellation tokens ([`function_call_error.rs:3`](../../.research/codex/source/codex-rs/tools/src/function_call_error.rs#L3), [`parallel.rs:175`](../../.research/codex/source/codex-rs/core/src/tools/parallel.rs#L175)).

Kiki maps individual read failures to Python exceptions, while execution cancellation or timeout drops the active checkout and recovers the last trusted checkpoint ([`arena.rs:897`](../../src/arena.rs#L897), [`arena.rs:450`](../../src/arena.rs#L450), [`arena.rs:547`](../../src/arena.rs#L547)). Its execution evidence currently represents one pending read plus an ordered sequence of settled calls ([`arena.rs:265`](../../src/arena.rs#L265), [`arena.rs:288`](../../src/arena.rs#L288)).

## Conventions & notable decisions

- **Concurrent work, ordered model context:** Maki, Pi, and Codex all allow work to complete asynchronously while preserving the model's original call order in submitted results ([Maki `tool_dispatch.rs:422`](../../.research/maki/source/maki-agent/src/agent/tool_dispatch.rs#L422), [Pi `agent-loop.ts:540`](../../.research/pi/source/packages/agent/src/agent-loop.ts#L540), [Codex `turn.rs:2158`](../../.research/codex/source/codex-rs/core/src/session/turn.rs#L2158)).
- **Mutation-aware admission differs:** Maki broadly fans out a model turn, Pi serialises only same-file mutations, and Codex lets each executor declare parallel safety under a shared read/write gate ([Maki `tool_dispatch.rs:422`](../../.research/maki/source/maki-agent/src/agent/tool_dispatch.rs#L422), [Pi `file-mutation-queue.ts:29`](../../.research/pi/source/packages/coding-agent/src/core/tools/file-mutation-queue.ts#L29), [Codex `tool_executor.rs:125`](../../.research/codex/source/codex-rs/tools/src/tool_executor.rs#L125), [Codex `parallel.rs:154`](../../.research/codex/source/codex-rs/core/src/tools/parallel.rs#L154)).
- **Code-arena concurrency is explicit in both prompt and bridge:** Maki couples async/gather prompt examples with a call-ID batch protocol and concurrent host dispatch ([`code_execution/init.lua:113`](../../.research/maki/source/plugins/code_execution/init.lua#L113), [`runner.rs:205`](../../.research/maki/source/maki-interpreter/src/runner.rs#L205), [`api/interpreter.rs:163`](../../.research/maki/source/maki-lua/src/api/interpreter.rs#L163)).
- **Kiki's outer model tool policy and inner arena concurrency are separate:** `parallel_tool_calls: false` applies to the sole `execute_python` provider tool, while nested concurrency is determined by the Monty event loop in `drive` ([`openai.rs:135`](../../src/openai.rs#L135), [`arena.rs:725`](../../src/arena.rs#L725)).
- **Smolagents makes model-facing Python interfaces concrete in the prompt:** generated function signatures, argument descriptions, return types, and structured result schemas tell code-writing models how to call tools and use returned values ([`tools.py:254`](../../.research/smolagents/source/src/smolagents/tools.py#L254), [`code_agent.yaml:132`](../../.research/smolagents/source/src/smolagents/prompts/code_agent.yaml#L132)). Its synchronous code-agent execution is distinct from Kiki's async Monty host-function contract ([`local_python_executor.py:915`](../../.research/smolagents/source/src/smolagents/local_python_executor.py#L915), [`arena.rs:795`](../../src/arena.rs#L795)).
