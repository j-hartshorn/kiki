# Research: GPT-5.6 Sol, Terra and Luna pricing

## Scope

This document catalogues the published direct OpenAI API pricing, token limits, usage-tier limits, processing modes, prompt-cache rules and related charges for GPT-5.6 Sol, Terra and Luna. Prices and documentation were checked on 3 September 2026.

The main price tables are direct OpenAI pay-as-you-go API prices. This research does not establish ChatGPT or Codex subscription entitlements, negotiated Enterprise discounts, or terms offered by gateways and resellers. Amazon Bedrock is covered only to distinguish its AWS-owned billing path. OpenAI's pages are living documents without visible revision dates, so this is a point-in-time record rather than a guarantee of future pricing.

## Summary

- The three IDs are separate OpenAI models rather than client-side aliases: Sol is the flagship tier, Terra is the intelligence/cost tier, and Luna is the cost-sensitive high-volume tier. `gpt-5.6` aliases Sol ([model catalogue](https://developers.openai.com/api/docs/models)).
- All three advertise a 1,050,000-token context window, a 128,000-token maximum output, image and text input, text output, and reasoning efforts from `none` through `max` ([Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol), [Terra](https://developers.openai.com/api/docs/models/gpt-5.6-terra), [Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna)).
- Standard short-context prices per million tokens are, respectively, Sol `$4.00 / $0.40 / $5.00 / $20.00`, Terra `$2.00 / $0.20 / $2.50 / $12.00`, and Luna `$0.20 / $0.02 / $0.25 / $1.20` for input, cached input, cache writes and output ([pricing](https://developers.openai.com/api/docs/pricing)).
- A prompt exceeding 272,000 input tokens moves the whole request to long-context rates. In every published mode, long-context input, cached-input and cache-write rates are twice the short-context rates, while output is 1.5 times the short-context rate ([model references](https://developers.openai.com/api/docs/models/gpt-5.6-sol)).
- Batch and Flex currently have the same token prices, exactly half the corresponding Standard prices. Their service behaviour differs: Batch is asynchronous with a 24-hour window; Flex is synchronous but slower and can return uncharged resource-unavailable errors. Fast mode is twice the corresponding Standard price and shares Standard rate limits ([Batch](https://developers.openai.com/api/docs/guides/batch), [Flex](https://developers.openai.com/api/docs/guides/flex-processing), [Fast mode](https://developers.openai.com/api/docs/guides/fast-mode)).
- GPT-5.6 cacheable prefixes start at 1,024 visible input tokens. A write costs 1.25 times uncached input, a hit costs 0.1 times uncached input, and the only supported minimum TTL is 30 minutes after the latest write or reuse; prompt-cache application state is not retained beyond 24 hours ([prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching), [data retention](https://developers.openai.com/api/docs/guides/your-data)).
- The free API tier does not support these models. Sol and Terra have the same published RPM, TPM and Batch queue limits; Luna has materially higher TPM and queue limits at most paid tiers ([model references](https://developers.openai.com/api/docs/models/gpt-5.6-luna)).
- Sol's current prices are explicitly promotional through at least 21 November 2026. Eligible regional-processing traffic adds 10%, and OpenAI publishes no replacement Sol price yet ([pricing](https://developers.openai.com/api/docs/pricing)).

#### Short- and long-context boundary

Prompts with more than 272,000 input tokens are billed at long-context rates for the entire request, not just the portion over the threshold. This changes all four token categories: uncached input, cached input, cache writes and output ([Sol pricing note](https://developers.openai.com/api/docs/models/gpt-5.6-sol), [Terra pricing note](https://developers.openai.com/api/docs/models/gpt-5.6-terra), [Luna pricing note](https://developers.openai.com/api/docs/models/gpt-5.6-luna)).

The model's 1.05M technical context window therefore spans two billing bands. A client can support the full window while still choosing a lower configured limit to avoid accidentally moving a request into the higher band.

#### Billing basis

- OpenAI states token prices per one million tokens. The examined pages do not document a minimum billable text-token quantity or per-request text-token rounding rule ([pricing](https://developers.openai.com/api/docs/pricing)).
- Responses, Chat Completions, Realtime, Batch and Assistants APIs do not have a separate endpoint fee. Model input/output and any applicable tool charges are billed instead ([pricing](https://developers.openai.com/api/docs/pricing#tools)).
- Image inputs are converted to input tokens based on dimensions and detail level, then charged at the selected model's input rate. The calculator's estimate excludes other prompt tokens, output, caching, long-context rates and regional uplift, and final image billing can differ by one token due to rounding ([image input cost calculator](https://developers.openai.com/api/docs/guides/image-cost-calculator)).

### 3. Processing-mode behaviour

The identical-looking Batch and Flex rows in the price matrix are not interchangeable services.

#### Standard

Standard is the ordinary pay-as-you-go service tier. Its published per-model RPM and TPM limits are in [section 5](#5-rate-and-usage-limits). Standard is also the reference price from which the current Batch/Flex discount and Fast premium can be read ([pricing](https://developers.openai.com/api/docs/pricing)).

#### Batch

The Batch API processes an asynchronous input file at 50% below Standard prices, uses a separate rate-limit pool, and has a 24-hour completion window ([Batch guide](https://developers.openai.com/api/docs/guides/batch)). Operational limits and caveats are:

- One batch may contain at most 50,000 requests and its input file may be at most 200 MB.
- An organisation may create up to 2,000 batches per hour.
- Each model has a queued-input-token limit. Pending jobs count until they complete.
- The Batch rate-limit pool has no separate output-token queue limit, but each response still has the model's 128,000-token maximum output.
- A batch that misses its 24-hour window expires. Completed responses are available in the output file and are charged; unfinished requests are cancelled and are not reported as successful. OpenAI deletes the output file 30 days after completion.
- Output file order is not guaranteed to match input order.

All of these are service limits rather than additional prices ([Batch rate limits and expiration](https://developers.openai.com/api/docs/guides/batch#rate-limits)).

#### Flex

Flex uses the same token prices as Batch but handles individual Responses or Chat Completions requests. In exchange for the lower rate, it has slower response times and occasional resource unavailability; OpenAI labels it beta with limited model availability ([Flex guide](https://developers.openai.com/api/docs/guides/flex-processing)).

- Select it with `service_tier: "flex"`.
- Official SDKs default to a 10-minute timeout. OpenAI's examples increase this to 15 minutes for long or complex work.
- Capacity exhaustion can return `429 Resource Unavailable`. The failed attempt is not charged.
- After `429 Resource Unavailable`, retry with `service_tier: "auto"` or omit the parameter to use the project's default tier. That may be Standard or Fast, with pricing determined by the tier actually used.
- Prompt-cache discounts still apply.

#### Fast mode

Fast mode is the renamed Priority service tier. Both `service_tier: "fast"` and `service_tier: "priority"` select it; GPT-5.6 responses still report `priority` in the returned service-tier field. The current Fast token prices are twice the matching Standard rates ([Fast mode guide](https://developers.openai.com/api/docs/guides/fast-mode)).

- OpenAI advertises up to 2.5 times faster speed and more consistent latency; that is a service claim, not a guaranteed speed for every request.
- Fast and Standard traffic share the same per-model rate limit.
- If traffic ramps too quickly, OpenAI may downgrade some Fast requests to Standard speed, return `service_tier: "default"`, and charge Standard rates.
- OpenAI's rule of thumb after reaching one million input TPM is to increase traffic by no more than 50% every 15 minutes. The actual ramp threshold varies by model and conditions, and all of an organisation's traffic across projects contributes to the same Fast ramp-rate limit.
- Cached-input discounts, images and long context remain supported. Fine-tuned models and embeddings are not supported in Fast mode.
- Availability varies by jurisdiction. Fast mode is separate from legacy Scale Tier capacity purchases; Reserved Tier can cover eligible Standard and Fast traffic across context lengths and regions.

#### Reserved Tier and Ultrafast

GPT-5.6 uses OpenAI's Enterprise-only Reserved Tier rather than Scale Tier. It prepurchases capacity for a specific model in dollars per minute, can cover Standard and Fast traffic across context lengths and eligible regions, and adds capacity beyond ordinary rate limits. OpenAI does not publish a fixed GPT-5.6 dollars-per-minute schedule; the `$2/min` figure on the page is an explanatory example, not a list price ([Reserved Tier](https://openai.com/api-reserved-tier/)).

Reserved Tier excludes Batch and Flex. Reservation burn-down is calculated at list prices, with discounts applied when purchasing the dollar-per-minute reservation. Overage is billed at the selected tier's normal discounted pay-as-you-go rate where applicable. Ultrafast is mentioned only as a limited-preview option with no public token or capacity price ([Reserved Tier](https://openai.com/api-reserved-tier/)). OpenAI's older Scale Tier page explicitly directs GPT-5.6 customers to Reserved Tier ([Scale Tier](https://openai.com/api-scale-tier/)).

### 4. Prompt-cache token rules

GPT-5.6 introduced paid cache writes and both implicit and explicit breakpoints. The complete current behaviour is in OpenAI's [prompt-caching guide](https://developers.openai.com/api/docs/guides/prompt-caching).

| Cache property | GPT-5.6 behaviour |
| --- | --- |
| Minimum cacheable prefix | 1,024 visible input tokens; hidden OpenAI system tokens do not count |
| Read price | 0.1 times the applicable uncached-input price |
| Write price | 1.25 times the applicable uncached-input price |
| Breakpoint modes | Implicit and explicit-only |
| Writes per request | At most four; an implicit breakpoint consumes one slot |
| Breakpoints considered on reads | Up to the latest 50, longest matching prefix first |
| Cached-token reporting | Exact eligible boundary, excluding hidden tokens |
| TTL control | `prompt_cache_options.ttl` |
| Supported TTL | `30m`, also the default |
| Lifetime | At least 30 minutes after the latest write or reuse; OpenAI may retain it longer, but not beyond 24 hours |

Cache-write pricing applies only to tokens through an eligible breakpoint. In implicit mode, OpenAI places that breakpoint at the latest eligible user or tool message. In explicit-only mode, a request without an explicit breakpoint neither uses prompt caching nor creates a cache write. A later request receives the discounted read rate only when its rendered prefix matches through an eligible breakpoint. The rendered prefix includes OpenAI instructions, developer messages, tools, conversation history and multimodal content, so changing content or relevant settings before a breakpoint prevents reuse after that point ([breakpoint modes](https://developers.openai.com/api/docs/guides/prompt-caching#how-caching-works), [prompt matching](https://developers.openai.com/api/docs/guides/prompt-caching#what-is-cached)).

For a completely reused eligible prefix, one write plus one read costs 1.35 times ordinary uncached input, compared with 2 times for two uncached passes. The cache becomes progressively cheaper with more hits, but eligible tokens written and never reused cost 25% more than ordinary input ([GPT-5.6 caching economics](https://developers.openai.com/api/docs/guides/prompt-caching#how-caching-works)).

Cache hits are not guaranteed. Entries live on individual machines; traffic over 15 requests per minute can overflow to machines without the entry. `prompt_cache_key` improves routing affinity but does not pin traffic or guarantee a hit. Caches are not shared between organisations or across regional-processing boundaries ([cache location](https://developers.openai.com/api/docs/guides/prompt-caching#cache-location)).

#### Published model limits

`RPM` means requests per minute, `TPM` tokens per minute, and `Batch queue` the number of pending input tokens allowed for that model. Free-tier use is unsupported for all three models ([Sol limits](https://developers.openai.com/api/docs/models/gpt-5.6-sol), [Terra limits](https://developers.openai.com/api/docs/models/gpt-5.6-terra), [Luna limits](https://developers.openai.com/api/docs/models/gpt-5.6-luna)).

#### Usage-tier qualification

OpenAI's high-level tier thresholds and monthly organisation usage limits are currently ([rate-limit guide](https://developers.openai.com/api/docs/guides/rate-limits#usage-tiers)):

| Tier | Published qualification | Monthly usage limit |
| --- | --- | ---: |
| Free | User in an allowed geography | $100 |
| 1 | $5 paid | $100 |
| 2 | $50 paid | $500 |
| 3 | $100 paid | $1,000 |
| 4 | $250 paid | $5,000 |
| 5 | $1,000 paid | $200,000 |

These are usage ceilings and graduation thresholds, not token prices or configurable project spend limits.

#### Rate-limit caveats

- Limits apply at organisation and project level rather than per user. The account's [Limits page](https://platform.openai.com/settings/organization/limits) is authoritative because approved or negotiated limits can differ.
- RPM, TPM, daily limits, Batch queue and monthly usage limits are independent constraints; the first exhausted constraint blocks further work.
- Some model families share limits. A shared TPM pool is consumed collectively by every model listed in that pool.
- Long-context requests can have a separate account limit visible in the developer console.
- Fast and Standard share limits. Batch uses a separate pool and does not consume synchronous per-model TPM, although pending Batch input counts against the model's Batch queue.
- OpenAI estimates token-rate consumption from the greater of `max_tokens` and an estimate based on request character count, so an unnecessarily high output cap can exhaust TPM earlier than actual output usage suggests.
- A `slow_down` response can occur before RPM or TPM is exhausted when traffic rises too quickly ([rate-limit guide](https://developers.openai.com/api/docs/guides/rate-limits)).

### 6. Tool and multimodal charges

Sol, Terra and Luna support Web Search, File Search, Image Generation, Code Interpreter, Hosted Shell, Apply Patch, Skills, Computer Use, MCP and Tool Search through the Responses API ([model references](https://developers.openai.com/api/docs/models/gpt-5.6-sol#tools)). Support does not imply that every tool is included in the text-token price.

OpenAI publishes these generic charges alongside model tokens ([tool pricing](https://developers.openai.com/api/docs/pricing#tools)):

| Facility | Published charge | Additional token treatment |
| --- | ---: | --- |
| Web Search | $10.00 per 1,000 calls | Retrieved search-content tokens billed at the chosen model's rate |
| Image Web Search | $10.00 per 1,000 calls | Retrieved content tokens billed at the chosen model's rate |
| Web Search Preview for reasoning models | $10.00 per 1,000 calls | Retrieved content tokens billed at the chosen model's rate |
| File Search storage | $0.10 per binary GB-day; first GB free | Storage charge, not model tokens |
| File Search calls | $2.50 per 1,000 calls | Applies to Responses API File Search |
| Hosted Shell or Code Interpreter, 1 GB | $0.03 per 20-minute container session | Model tokens remain separately billable |
| Hosted Shell or Code Interpreter, 4 GB | $0.12 per 20-minute container session | Model tokens remain separately billable |
| Hosted Shell or Code Interpreter, 16 GB | $0.48 per 20-minute container session | Model tokens remain separately billable |
| Hosted Shell or Code Interpreter, 64 GB | $1.92 per 20-minute container session | Model tokens remain separately billable |

Eligible container sessions can instead be metered by the minute with a five-minute minimum. Tokens used by built-in tools are charged at the chosen model's input/output rates. The pricing page does not list a separate function-calling, structured-output, MCP, Apply Patch, Skills, Computer Use or Tool Search call fee. Image generation uses separately priced image-generation models and is not represented by a Sol, Terra or Luna text-output rate ([pricing](https://developers.openai.com/api/docs/pricing)).

### 7. Pricing caveats and provider boundaries

#### Promotional Sol pricing

OpenAI says the published Sol prices are promotional through at least 21 November 2026. It does not publish the eventual replacement rates or promise that the promotion ends exactly on that date ([pricing](https://developers.openai.com/api/docs/pricing)). Terra and Luna are not labelled promotional on the examined page.

#### Regional processing

Eligible regional-processing endpoints for eligible models released on or after 5 March 2026 carry a 10% uplift. The source does not establish that every non-token tool, container or storage charge receives that uplift ([pricing](https://developers.openai.com/api/docs/pricing), [data residency](https://developers.openai.com/api/docs/guides/your-data#data-residency-controls)).

At the captured point in time, the GPT-5.6 processing matrix is:

| Region | Regional processing for GPT-5.6 |
| --- | --- |
| United States | Sol, Terra and Luna through Responses, Chat Completions and Batch |
| Europe (EEA and Switzerland) | Sol, Terra and Luna through Responses, Chat Completions and Batch |
| United Arab Emirates | Luna only through Responses and Chat Completions |
| Australia, Canada, Japan, India, Singapore, South Korea and United Kingdom | Regional storage, but no regional processing |

Non-US regions require approved abuse-monitoring controls and a Modified Retention amendment; the UAE requires additional approval. Regional storage does not imply regional inference. Chat Completions cannot set `store=true` outside the US, and Responses cannot use background mode in the EU ([regional support and endpoint limitations](https://developers.openai.com/api/docs/guides/your-data#which-models-and-features-are-eligible-for-data-residency)).

#### Amazon Bedrock and other routes

Amazon Bedrock uses `openai.gpt-5.6-*` IDs but AWS controls account access, regions, quotas and billing. It offers on-demand inference rather than OpenAI service tiers, so the direct OpenAI Standard, Batch, Flex, Fast and Reserved Tier semantics do not transfer to Bedrock. OpenAI explicitly says Bedrock prices can differ from direct API pricing, including regional premiums and AWS commercial terms; direct OpenAI rates must not be used as an AWS quote ([Amazon Bedrock features](https://developers.openai.com/api/docs/guides/amazon-bedrock#responses-api-feature-availability), [Amazon Bedrock pricing](https://developers.openai.com/api/docs/guides/amazon-bedrock#pricing)). This research does not establish commercial terms for other gateways or resellers.

#### Fine-tuning, audio and subscriptions

The three model cards mark fine-tuning, audio and video as unsupported, so there is no GPT-5.6 Sol/Terra/Luna fine-tuning, audio-token or video-token rate to catalogue ([model references](https://developers.openai.com/api/docs/models/gpt-5.6-sol)). This research does not establish ChatGPT or Codex plan entitlements; the direct API matrix must not be treated as a subscription allowance.

#### Local Pi client behaviour

The installed Pi 0.84.4 model catalogue exposes all three direct OpenAI IDs with a 272,000-token context and 128,000-token output cap. Its documentation says this lower client-side default deliberately keeps requests inside OpenAI's short-context price tier; a `modelOverrides` entry can raise `contextWindow` to 1,050,000 without replacing the built-in pricing metadata. This is a client guardrail, not an OpenAI model limitation (`/opt/homebrew/lib/node_modules/@earendil-works/pi-coding-agent/docs/models.md`, inspected 3 September 2026).

## Conventions & notable decisions

- Prices are normalised to dollars per million tokens because that is OpenAI's published unit. No conversion to per-request cost is possible without actual uncached input, cache-write, cache-read and output usage.
- The price matrix keeps cache writes separate from ordinary input. Cost estimators must apply the 25% write premium only to tokens through a breakpoint that actually creates a cache entry.
- The 272,000-token boundary is request-wide. Cost estimators must switch the whole request to the long-context rate set rather than price only excess tokens at the higher rate.
- Batch and Flex share prices but not delivery semantics. A cost model can share their rate table; an operational model cannot treat them as the same service.
- The model-card rate-limit tables are public defaults. Actual organisation limits, shared pools, regional eligibility, Reserved Tier capacity and negotiated discounts remain account-specific.
