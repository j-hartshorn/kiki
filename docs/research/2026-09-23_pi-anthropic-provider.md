# Research: Pi Anthropic provider integration

## Scope

This report traces pi's Anthropic Messages adapter and its model/auth wiring, the shared message-history conversion with OpenAI Responses, and how the coding agent persists and renders assistant thinking. The source is `@earendil-works/pi-ai` `0.84.3`, vendored at `.research/pi/source`; all citations are relative to that directory. (`packages/ai/src/api/anthropic-messages.ts:1-44`; `packages/ai/src/providers/anthropic.ts:1-58`; `packages/ai/src/api/transform-messages.ts:1-10`; `packages/ai/src/api/openai-responses-shared.ts:138-172`; `packages/coding-agent/src/core/agent-session.ts:652-670`)

## Summary

- `streamSimple()` requests adaptive thinking for models marked `forceAdaptiveThinking`; other reasoning models use token budgets. The model generator assembles built-in adaptive support and per-level mappings. (`packages/ai/src/api/anthropic-messages.ts:801-870`; `packages/ai/scripts/generate-models.ts:562-579,898-928`)
- Thinking text and signatures are stored in assistant message content. When provider, API and model all match exactly, signed blocks are kept for replay. Cross-model transformations turn non-empty thinking text into ordinary text and drop empty or redacted thinking blocks. (`packages/ai/src/types.ts:356-364`; `packages/ai/src/api/transform-messages.ts:96-128`)
- Anthropic cache markers can go on the system prompt, the last tool definition and the last user-message block. `PI_CACHE_RETENTION=long` requests a one-hour TTL where supported. (`packages/ai/src/api/anthropic-messages.ts:50-73,1010-1032,1295-1313,1354-1360`)
- Anthropic usage separates input, cache-read, cache-write and output tokens; reported thinking tokens are a subset of output. Costs use the selected model's per-million-token rates, with one-hour cache writes priced at twice the input rate. (`packages/ai/src/api/anthropic-messages.ts:599-610,741-767`; `packages/ai/src/models.ts:879-896`; `packages/ai/src/types.ts:385-402`)
- The adapter builds a streaming Messages request with `model`, `messages` and `max_tokens`, plus optional `system`, `tools`, thinking, metadata and tool-choice fields. Auth is resolved for the model's provider before dispatch. (`packages/ai/src/api/anthropic-messages.ts:973-1105`; `packages/coding-agent/src/core/model-runtime.ts:573-603`)
- The SSE parser handles the documented message and content-block events and ignores unknown event names. It raises errors for SSE `error` events or for streams missing `message_stop`, and maps provider stop reasons to pi stop reasons. (`packages/ai/src/api/anthropic-messages.ts:319-328,460-498,1365-1387`)
- The shared retry policy treats 429 and server errors, including 529, as retryable when retries are configured. It honours server `retry-after-ms` and `retry-after` values up to a delay limit. (`packages/ai/src/utils/provider-retry.ts:23-67,101-128`)

## Findings

### 1. Thinking

The provider-neutral `SimpleStreamOptions.reasoning` accepts the pi levels `minimal`, `low`, `medium`, `high`, `xhigh` and `max`; the agent loop represents `off` by leaving the reasoning option out. (`packages/ai/src/types.ts:314-322`; `packages/agent/src/agent-loop.ts:234-243`) Model metadata has a `thinkingLevelMap` that translates pi levels into model-specific values: `null` marks a level as unsupported, and a missing mapping falls back to provider defaults. (`packages/ai/src/types.ts:82-85,826-835`)

For Anthropic Messages models marked `compat.forceAdaptiveThinking`, `streamSimple()` maps the requested level to `effort` and turns thinking on. The adapter sends `thinking: { type: "adaptive", display }` and, when an effort is set, sends it as `output_config.effort`. `xhigh` is cast because the SDK type may not list it yet. (`packages/ai/src/api/anthropic-messages.ts:801-822,843-853,1061-1079`) The mapping checks `model.thinkingLevelMap` first. Otherwise `minimal` and `low` map to `low`, `medium` to `medium` and `high` to `high`, and any other level falls back to `high`. (`packages/ai/src/api/anthropic-messages.ts:807-822`)

The generator marks Anthropic API models as adaptive when their IDs match its listed Opus 4.6+, Sonnet 4.6+/5 and Fable 5 patterns. Compatibility metadata can also force adaptive mode for custom Anthropic-compatible models. (`packages/ai/scripts/generate-models.ts:562-579,924-928`; `packages/ai/src/types.ts:682-691`) It adds `max` mappings for matching Opus 4.6 and Sonnet 4.6 IDs, and `xhigh` plus `max` mappings for matching Opus 4.7/4.8/5, Sonnet 5 and Fable 5 IDs. (`packages/ai/scripts/generate-models.ts:898-923`) Effort options generated from models.dev values can also fill in the map; values with no pi equivalent are left out. (`packages/ai/scripts/models-dev-reasoning-options.ts:18-42`; `packages/ai/scripts/generate-models.ts:489-516`)

Other reasoning models use budget-based thinking. Pi's default budgets are 1,024 tokens for `minimal`, 2,048 for `low`, 8,192 for `medium` and 16,384 for `high`; `xhigh` and `max` count as `high` here. (`packages/ai/src/api/simple-options.ts:54-72`) The helper adjusts the output ceiling to fit the budget, keeps at least 1,024 answer tokens when clamping, and the Anthropic adapter then sends `thinking: { type: "enabled", budget_tokens: ... }`. (`packages/ai/src/api/simple-options.ts:74-100`; `packages/ai/src/api/anthropic-messages.ts:855-870,1080-1085`) With thinking off, the adapter sends `thinking: { type: "disabled" }` unless the model's `off` mapping is `null`, in which case it leaves the field out. (`packages/ai/src/api/anthropic-messages.ts:1087-1089`)

`AnthropicOptions.thinkingDisplay` accepts `summarized` or `omitted`. When thinking is on, the adapter defaults to `summarized`, including for models whose API default the code documents as `omitted`. (`packages/ai/src/api/anthropic-messages.ts:238-252,1061-1069`) The option's documentation says `omitted` returns an empty thinking field but keeps the encrypted signature for multi-turn continuity. (`packages/ai/src/api/anthropic-messages.ts:242-250`)

Anthropic thinking blocks become pi `thinking` content blocks. `thinking_delta` events append text and are emitted as stream deltas; signature deltas build up the block's signature. (`packages/ai/src/api/anthropic-messages.ts:621-636,653-700`) The interactive assistant renderer walks thinking in content order and renders non-empty thinking as italic Markdown. With `hideThinkingBlock` set, it shows the configured hidden-thinking label instead. (`packages/coding-agent/src/modes/interactive/components/assistant-message.ts:97-154`) Empty thinking content is not rendered. (`packages/coding-agent/src/modes/interactive/components/assistant-message.ts:97-112,127-143`)

### 2. Thinking block replay

Pi's `ThinkingContent` stores the readable `thinking` text and an optional provider-specific `thinkingSignature`. `redacted` marks safety-redacted content, whose opaque payload lives in the signature field. (`packages/ai/src/types.ts:356-364`) Completed assistant messages are appended to the session as message entries, keeping the assistant message object and its content. (`packages/coding-agent/src/core/agent-session.ts:652-670`; `packages/coding-agent/src/core/session-manager.ts:1057-1066`)

The Anthropic stream handler stores ordinary thinking signatures from `content_block_start` and appends `signature_delta` values. A `redacted_thinking` block becomes pi thinking text `"[Reasoning redacted]"`, with the opaque `data` stored as its signature and `redacted: true`. (`packages/ai/src/api/anthropic-messages.ts:621-635,692-697`) On replay, Anthropic conversion sends redacted blocks as `redacted_thinking` with the stored signature as `data`, and signed ordinary blocks as `thinking` with their signature. (`packages/ai/src/api/anthropic-messages.ts:1218-1252`) Empty signatures are turned into plain text by default. A model with `compat.allowEmptySignature` replays them as `thinking` with `signature: ""` instead. (`packages/ai/src/api/anthropic-messages.ts:185-193,1226-1247`)

By default the adapter requests the `interleaved-thinking-2025-05-14` beta for non-adaptive models. It skips the header for adaptive models, where the code treats interleaved thinking as built in; callers can also switch the option off. (`packages/ai/src/api/anthropic-messages.ts:176,254-260,880-898`)

### 3. Cross-provider history

The shared `transformMessages()` treats a message as "same model" when provider, API and model ID all match. For an exact match it keeps thinking blocks that have signatures, including ones with empty text, and also keeps non-empty unsigned thinking blocks. (`packages/ai/src/api/transform-messages.ts:96-111`) For any other target, non-empty unredacted thinking becomes ordinary text, empty and redacted thinking are dropped, and cross-model tool calls also lose `thoughtSignature`. (`packages/ai/src/api/transform-messages.ts:101-128`)

| Source history and target | Transformation and replay result |
|---|---|
| Anthropic thinking to a different provider or model | Non-empty thinking text is sent as ordinary assistant text; the Anthropic signature is dropped. Empty and redacted thinking are dropped too. (`packages/ai/src/api/transform-messages.ts:101-128`) |
| OpenAI Responses reasoning to Anthropic | OpenAI Responses stores its reasoning item as JSON in `thinkingSignature` and uses the summary/content as thinking text. For a different target, non-empty text becomes ordinary text and empty blocks are dropped, so the OpenAI encrypted reasoning is never sent as an Anthropic thinking signature. (`packages/ai/src/api/openai-responses-shared.ts:680-690`; `packages/ai/src/api/transform-messages.ts:101-128`) |
| OpenAI Responses reasoning back to the exact same model | The Responses converter parses the stored signature JSON and adds the resulting reasoning item to the request; the stream handler stores the completed reasoning item as JSON in the signature. (`packages/ai/src/api/openai-responses-shared.ts:218-225,680-690`) |
| Anthropic thinking back to the exact same model | The shared transform keeps signed blocks, and Anthropic conversion sends the signature with the thinking block or, for redacted blocks, as `redacted_thinking.data`. (`packages/ai/src/api/transform-messages.ts:101-111`; `packages/ai/src/api/anthropic-messages.ts:1218-1252`) |

For OpenAI Responses, tool IDs have the form `call_id|item_id`. When converting history, the adapter sanitises the ID parts, hashes foreign Responses item IDs into an `fc_` ID, and removes item IDs in some different-model cases to avoid pairing validation errors. (`packages/ai/src/api/openai-responses-shared.ts:150-166,209-265`) Anthropic instead replaces characters outside `[a-zA-Z0-9_-]` with `_` and truncates IDs to 64 characters; `transformMessages()` applies the same mapping to the matching tool results. (`packages/ai/src/api/anthropic-messages.ts:981-1002,1116-1118`; `packages/ai/src/api/transform-messages.ts:75-96`)

The shared transform also drops assistant messages whose stop reason is `error` or `aborted`, and inserts synthetic error tool results for tool calls that have no matching result. (`packages/ai/src/api/transform-messages.ts:149-205`)

### 4. Prompt caching

The cache-retention option is `none`, `short` or `long`. With no explicit option, the Anthropic adapter checks `PI_CACHE_RETENTION=long` and otherwise uses `short`. (`packages/ai/src/types.ts:108`; `packages/ai/src/api/anthropic-messages.ts:50-56`) `none` turns cache markers off. The other modes create an `ephemeral` cache marker; `long` adds `ttl: "1h"` when the model supports long retention and otherwise leaves the TTL out. (`packages/ai/src/api/anthropic-messages.ts:60-73`; `packages/ai/src/types.ts:658-660`)

When caching is on, the adapter marks the system-prompt text, the last tool definition (when tool caching is supported), and the last block of the last user message if that block is text, an image or a tool result. (`packages/ai/src/api/anthropic-messages.ts:1010-1032,1295-1313,1354-1360`) For OAuth requests, the injected Claude Code identity system text also gets a cache marker. (`packages/ai/src/api/anthropic-messages.ts:1010-1024`)

### 5. Usage and cost mapping

On `message_start`, Anthropic `input_tokens`, `output_tokens`, `cache_read_input_tokens` and `cache_creation_input_tokens` fill pi's `input`, `output`, `cacheRead` and `cacheWrite`; the one-hour cache-creation count fills `cacheWrite1h`. (`packages/ai/src/api/anthropic-messages.ts:599-610`) Usage fields present in `message_delta` replace the matching values, and missing fields leave the earlier values alone. `output_tokens_details.thinking_tokens` is stored as `reasoning`, which pi defines as a subset of `output`. (`packages/ai/src/api/anthropic-messages.ts:741-767`; `packages/ai/src/types.ts:385-402`)

Anthropic doesn't give a total here, so pi computes `totalTokens` as input + output + cache-read + cache-write tokens. (`packages/ai/src/api/anthropic-messages.ts:608-610,765-767`) Cost rates are in dollars per million tokens for input, output, cache read and cache write. The cost function picks the highest applicable input-usage tier, computes each category's cost and adds them up. (`packages/ai/src/types.ts:803-815`; `packages/ai/src/models.ts:879-896`) One-hour cache writes are a subset of cache writes and are priced at twice the model's input rate, not the normal cache-write rate. (`packages/ai/src/types.ts:387-388`; `packages/ai/src/models.ts:890-896`)

The generator builds Anthropic model entries from models.dev metadata, copying its input, output, cache-read and cache-write rates; the provider model shard imports those generated values from `./data/anthropic.json`. (`packages/ai/scripts/generate-models.ts:1480-1503`; `packages/ai/src/providers/anthropic.models.ts:1-8`) If a response names an allowed server-side fallback model, the adapter uses that fallback's cost metadata for the usage calculation. (`packages/ai/src/api/anthropic-messages.ts:592-610`)

### 6. Request shape

The adapter builds a streaming request with `model`, the converted `messages`, `max_tokens` (the option value or the model cap) and `stream: true`. (`packages/ai/src/api/anthropic-messages.ts:973-1007`) `streamSimple()` sets up base options with a token cap clamped to the context window, and for budget-based thinking it adjusts the cap to fit the thinking budget. (`packages/ai/src/api/simple-options.ts:13-17,24-50,79-100`; `packages/ai/src/api/anthropic-messages.ts:855-870`)

A system prompt, when given, is sent as a system text block. OAuth requests prepend the text `You are Claude Code, Anthropic's official CLI for Claude.` (`packages/ai/src/api/anthropic-messages.ts:1010-1032`) Tools are left out when none are active; otherwise immediate and deferred tool definitions are converted into the request. (`packages/ai/src/api/anthropic-messages.ts:1040-1060`) Tool-choice strings become `{ type: ... }`, and an explicit `{ type: "tool", name }` choice is passed through as is. (`packages/ai/src/api/anthropic-messages.ts:1098-1104`)

Temperature is sent only when it is set, thinking is off and model compatibility allows it. (`packages/ai/src/api/anthropic-messages.ts:1037-1039`) Metadata forwards a string `user_id`, and configured fallback models go in the `fallbacks` field. (`packages/ai/src/api/anthropic-messages.ts:1091-1110`)

The client headers include pi's `User-Agent`, `accept: application/json` and `anthropic-dangerous-direct-browser-access: true`, merged with model and request headers. (`packages/ai/src/api/anthropic-messages.ts:281-290,901-970`) Beta headers can include interleaved thinking, fine-grained tool streaming when the compatibility settings need it, and server-side fallback when fallback models are configured. (`packages/ai/src/api/anthropic-messages.ts:175-177,888-898`) OAuth-token requests also send Claude Code/OAuth beta values, the Claude CLI user agent and `x-app: cli`. GitHub Copilot has its own bearer-auth branch and header construction. (`packages/ai/src/api/anthropic-messages.ts:901-945`)

### 7. Streaming parsing and stop reasons

The SSE decoder recognises `message_start`, `message_delta`, `message_stop`, `content_block_start`, `content_block_delta` and `content_block_stop`. An SSE `error` event throws its data, other event names are ignored, and malformed JSON in a recognised event is reported along with the event and raw data. (`packages/ai/src/api/anthropic-messages.ts:319-328,460-493`) A stream that saw `message_start` but ended without `message_stop` is treated as an error. (`packages/ai/src/api/anthropic-messages.ts:460-498`)

Text, thinking and tool-input deltas in content blocks become pi text, thinking and tool-call stream events. Signature deltas update the thinking signature without emitting a separate pi event. (`packages/ai/src/api/anthropic-messages.ts:611-701`; `packages/ai/src/types.ts:535-544`) When processing ends, a stop reason that is still pending, or an `error`/`aborted` stop, becomes a stream error. (`packages/ai/src/api/anthropic-messages.ts:780-799`)

The stop mapping is `end_turn` → `stop`, `max_tokens` → `length`, `tool_use` → `toolUse`, and `pause_turn` or `stop_sequence` → `stop`. (`packages/ai/src/api/anthropic-messages.ts:1365-1385`) `refusal` becomes an error, using `stop_details.explanation` when present; `sensitive` becomes an error with a fixed message; unknown stop reasons throw. (`packages/ai/src/api/anthropic-messages.ts:1376-1387`)

### 8. Retries and errors

Anthropic requests set the SDK request's `maxRetries` to zero and wrap response acquisition in `retryProviderRequest`, passing through the configured retry count, retry-delay limit and abort signal. (`packages/ai/src/api/anthropic-messages.ts:570-584`) The shared retry helper defaults to zero retries when no count is given. (`packages/ai/src/utils/provider-retry.ts:101-128`)

The helper retries 408, 409, 429 and any status of 500 or above, unless `x-should-retry` is explicitly `false`. So 529 is covered by the generic server-error rule, not a special Anthropic branch. (`packages/ai/src/utils/provider-retry.ts:23-37`) It prefers `retry-after-ms`, then `retry-after` as seconds or an HTTP date. Without either, it backs off exponentially from 500 ms up to 8 seconds with downward jitter. (`packages/ai/src/utils/provider-retry.ts:52-67`) Server-requested delays are capped at 60 seconds by default. A longer delay fails unless the configured limit is zero, and the wait can be aborted. (`packages/ai/src/utils/provider-retry.ts:1,40-49,69-96`)

### 9. Provider/model registry and credentials

Anthropic model metadata sets the provider ID `anthropic`, API ID `anthropic-messages` and base URL `https://api.anthropic.com`. Cost, reasoning capability, input modalities and token limits come from models.dev metadata. (`packages/ai/scripts/generate-models.ts:1480-1503`) `anthropicProvider()` registers the generated Anthropic model shard and binds that catalogue to the Anthropic Messages API implementation. (`packages/ai/src/providers/anthropic.models.ts:1-8`; `packages/ai/src/providers/anthropic.ts:42-58`) `createProvider()` dispatches through the provider's API implementation using `model.api`, and the provider collection looks up the provider from `model.provider`. (`packages/ai/src/models.ts:762-789,629-633`)

The Anthropic provider supports API-key auth plus a separate OAuth auth handler. Its API-key resolver checks a stored key first, then `ANTHROPIC_AUTH_TOKEN` as a bearer `Authorization` header, then `ANTHROPIC_OAUTH_TOKEN` and `ANTHROPIC_API_KEY` as API-key values. (`packages/ai/src/providers/anthropic.ts:9-42,45-58`) In the shared resolver, stored credentials take precedence over ambient ones; environment auth is only consulted when no stored credential exists. (`packages/ai/src/auth/resolve.ts:42-99`) The adapter spots OAuth tokens by the `sk-ant-oat` substring and passes them as a bearer `authToken`; ordinary API keys go through the SDK's `apiKey` option. (`packages/ai/src/api/anthropic-messages.ts:873-875,925-970`)

The model runtime resolves auth for the selected model's provider before dispatch. If there is none, it raises `Provider is not configured: <provider>`. (`packages/coding-agent/src/core/model-runtime.ts:573-603`) The interactive `setModel()` path checks provider auth first and throws `No API key for <provider>/<model>` when it isn't configured. Available-model lists also leave out providers without configured auth. (`packages/coding-agent/src/core/agent-session.ts:1632-1639`; `packages/ai/src/models.ts:522-540`)

## Gaps

- The per-model numeric Anthropic rates live in a generated JSON file that the Anthropic model shard imports. The generator fetches models.dev data and emits provider JSON, so the TypeScript source shows the rate fields and how they are derived, but not the actual rate numbers, and this report doesn't list them. (`packages/ai/src/providers/anthropic.models.ts:1-8`; `packages/ai/scripts/generate-models.ts:1430-1434,1480-1503,2948-3002`)
- Behaviour can differ for Anthropic-compatible providers, because model compatibility fields control adaptive thinking, cache TTL, tool caching, eager tool streaming and signature replay. (`packages/ai/src/api/anthropic-messages.ts:180-199`; `packages/ai/src/types.ts:648-691`)
