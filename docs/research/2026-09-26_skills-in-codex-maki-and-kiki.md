# Research: Skills in Codex, Maki, and Kiki

## Scope

This document covers local `SKILL.md` discovery, metadata, prompt exposure, loading, resource access, and the Kiki seams those mechanisms touch. It describes the vendored Codex and Maki revisions in `.research` and Kiki as currently implemented. It does not cover remote skill registries, plugin installation, or the full Codex extension protocol.

## Summary

- Kiki's [vision](../VISION.md#L109) already names project `.agents/skills/` and user `~/.agents/skills/`, a catalog containing only names and descriptions, and an on-demand `load_skill` capability. No corresponding skill tool appears in Kiki's [active tool definitions](../../src/tools.rs#L589).
- Codex has a [layered set of local roots](../../.research/codex/source/codex-rs/ext/skills/src/host_roots.rs#L73), [validated frontmatter](../../.research/codex/source/codex-rs/skills/src/parser.rs#L43), a [bounded initial catalog](../../.research/codex/source/codex-rs/ext/skills/src/render.rs#L17), and [selected skill bodies](../../.research/codex/source/codex-rs/ext/skills/src/fragments.rs#L61) as separate model-context fragments.
- Maki implements skills as one [read-kind Lua tool](../../.research/maki/source/plugins/skill/init.lua#L136). It lists names and descriptions in the tool description, then returns a selected body when the tool is called [at lines 132–180](../../.research/maki/source/plugins/skill/init.lua#L132).
- Kiki assembles its [root and child prompts](../../src/prompt.rs#L45) from a Markdown base plus generated tool reference. Its [Python tool definitions](../../src/tools.rs#L589) produce both arena wrappers and model-visible signatures.
- Kiki's [normal file tools](../../src/tools.rs#L2327) accept workspace-relative paths. That makes supporting files in a user skill under `~/.agents/skills/` a distinct resource-access case from a project skill inside the workspace.
- Kiki's [system prompt](../../prompts/system.md#L35) currently says to treat all host-function output as untrusted data and not follow instructions in it. A loaded skill body returned through Python would reach model context through [execution feedback](../../src/agent.rs#L1325), where that rule currently has no skill-specific interpretation.

## Findings

### Codex local skills

Codex assembles skill roots from project configuration, a legacy user directory, `~/.agents/skills/`, system and admin directories, and repo `.agents/skills/` directories between the project root and current directory ([root construction](../../.research/codex/source/codex-rs/ext/skills/src/host_roots.rs#L73), [repo ancestor roots](../../.research/codex/source/codex-rs/ext/skills/src/host_roots.rs#L137)). Root scans are bounded by traversal depth, directory and entry counts, and concurrent loads ([discovery options](../../.research/codex/source/codex-rs/ext/skills/src/loader/discovery.rs#L17), [walk call](../../.research/codex/source/codex-rs/ext/skills/src/loader/discovery.rs#L65)). Missing roots produce an empty discovery result; scan errors become warnings ([discovery error handling](../../.research/codex/source/codex-rs/ext/skills/src/loader/discovery.rs#L87)). The loader retains first-discovered canonical file paths when roots overlap ([merge logic](../../.research/codex/source/codex-rs/ext/skills/src/loader/host_merge.rs#L201)).

Codex parses YAML frontmatter from `SKILL.md`. It requires delimiters and a nonempty description, defaults a missing name to the directory name, limits the name to 64 characters, and normalizes displayed scalar text to one line ([parser](../../.research/codex/source/codex-rs/skills/src/parser.rs#L30), [validation](../../.research/codex/source/codex-rs/skills/src/parser.rs#L64)). It also recognizes optional `agents/openai.yaml` metadata for interface, dependencies, and invocation policy; a failure in that optional file does not block `SKILL.md` loading ([metadata loader](../../.research/codex/source/codex-rs/ext/skills/src/loader/metadata.rs#L77)).

Codex places the available-skills catalog in a developer-role context fragment and selected skill contents in a user-role `<skill>` fragment ([fragment roles and markers](../../.research/codex/source/codex-rs/ext/skills/src/fragments.rs#L39), [selected body](../../.research/codex/source/codex-rs/ext/skills/src/fragments.rs#L76)). Its catalog has character or token budgets, and the extension caps a selected main prompt at 8,000 bytes ([catalog budgets](../../.research/codex/source/codex-rs/ext/skills/src/render.rs#L17), [body truncation](../../.research/codex/source/codex-rs/ext/skills/src/render.rs#L1176)). Its usage instructions distinguish a selected skill file from linked resources and tell the model to open the latter as needed ([catalog prompt](../../.research/codex/source/codex-rs/ext/skills/src/catalog_prompt.rs#L7)).

Codex's extension-backed skill reader scopes requests to an available package and resource identity, validates handles, and pages responses rather than treating every resource as an arbitrary host path ([reader schema](../../.research/codex/source/codex-rs/ext/skills/src/tools/read.rs#L34), [package selection](../../.research/codex/source/codex-rs/ext/skills/src/tools/read.rs#L82), [pagination](../../.research/codex/source/codex-rs/ext/skills/src/tools/read.rs#L155)). The app server can watch skill roots and invalidate cached catalogs on file changes ([watcher](../../.research/codex/source/codex-rs/app-server/src/skills_watcher.rs#L112)). Its guardian policy does not treat skill instructions as a source of user authorization ([policy template](../../.research/codex/source/codex-rs/core/assets/guardian/policy_template.md#L5)).

For direct-child plugin skills, Codex canonicalizes discovered file paths and rejects paths outside the plugin root ([plugin containment](../../.research/codex/source/codex-rs/ext/skills/src/loader/host.rs#L185)).

### Maki local skills

Maki's bundled plugin scans its own config directory, several personal compatibility directories, and `.maki`, `.claude`, `.opencode`, and `.agents` skill directories along project ancestors through the `.git` root ([root lists](../../.research/maki/source/plugins/skill/init.lua#L11), [discovery order](../../.research/maki/source/plugins/skill/init.lua#L98)). Later assignments by name replace earlier ones, so the order determines the winner ([skill map assignment](../../.research/maki/source/plugins/skill/init.lua#L35)); the [user documentation](../../.research/maki/source/site/docs/content/skills/_index.md#L14) describes project-over-personal precedence.

A child directory with a readable `SKILL.md` becomes a skill when its body is nonempty ([directory scan](../../.research/maki/source/plugins/skill/init.lua#L23)). YAML frontmatter is optional; its name and description are optional, and malformed YAML falls back to an empty metadata map ([frontmatter helper](../../.research/maki/source/plugins/skill/skill_helpers.lua#L3)). The startup catalog is an alphabetized name-and-description list inside the `skill` tool description ([list builder](../../.research/maki/source/plugins/skill/skill_helpers.lua#L21), [registration](../../.research/maki/source/plugins/skill/init.lua#L132)).

On each `skill(name)` call, Maki scans again and returns the body with its path and line numbers. An unknown name produces an error and a fresh available-skills list ([handler](../../.research/maki/source/plugins/skill/init.lua#L160)). The TUI renders loaded content in an expandable, highlighted tool view ([tool view](../../.research/maki/source/plugins/skill/init.lua#L181)). Other files in a skill directory are not loaded by the plugin; the docs instruct authors to link them from the body ([Maki skill docs](../../.research/maki/source/site/docs/content/skills/_index.md#L25)).

Maki's directory API follows symlinks during scans ([filesystem API](../../.research/maki/source/maki-lua/src/api/fs.rs#L367)), and the skill plugin reads the constructed `SKILL.md` path without a containment check ([scan](../../.research/maki/source/plugins/skill/init.lua#L23)).

Maki also ships a generated `maki-plugin-dev` skill. Its load handler writes a large Lua API reference to the state directory and points the body at that file, with an inline fallback when the write fails ([builtin resolver](../../.research/maki/source/plugins/skill/init.lua#L78)). The plugin's focused tests cover frontmatter parsing, catalog formatting, and the generated reference index ([skill tests](../../.research/maki/source/plugins/skill/tests/spec.lua#L20)).

### Kiki's current seams

Kiki's [vision](../VISION.md#L117) specifies exactly two initial skill roots and only name and description in initial model context; full `SKILL.md` loads on demand. It describes scripts, references, and assets as reachable through normal tools, while leaving installation and compatibility paths outside the initial scope ([vision details](../VISION.md#L119)). The same document calls for static prompt instructions to live in Markdown and dynamic metadata to be assembled by Rust ([prompt resources](../VISION.md#L126)).

At startup, `config::load` obtains the current directory and resolves the bundled or overridden prompt ([configuration input](../../src/config.rs#L454)). The prompt module appends a generated tool reference to the root base, while child prompts use the same base plus `prompts/subagent.md` and an effective child tool reference ([prompt assembly](../../src/prompt.rs#L45)). `main` gives the resolved prompt to the root model and the raw base to the child-runner factory ([fresh startup](../../src/main.rs#L275), [child construction](../../src/main.rs#L308)). A read-only child has a reduced tool reference and host enforcement ([child tool reference](../../src/arena.rs#L822), [dispatch check](../../src/tools.rs#L1833)).

The active Python host tools are a fixed Rust table of seven file/command capabilities, with subagent wrappers generated separately ([tool definitions](../../src/tools.rs#L589), [generated source](../../src/tools.rs#L634)). A tool added there affects bootstrap wrappers, type-check stubs, prompt signatures, dispatch, and trace labels ([private names](../../src/tools.rs#L67), [tool source](../../src/tools.rs#L682), [dispatch](../../src/tools.rs#L1851), [trace labels](../../src/tools.rs#L109)). The Arena recognizes private host names, queues pending calls, and returns correlated results to Monty ([function call handling](../../src/arena.rs#L1728)).

The normal file host holds a capability-style handle to the workspace root ([host construction](../../src/tools.rs#L1656)). Its direct filesystem calls reject absolute and parent paths, and reject traversal through symlinks ([path validation](../../src/tools.rs#L2327), [symlink handling](../../src/tools.rs#L3136)). The `run` command remains a separate shell capability with broader host access, as recorded in the existing [tool spec](../2026-09-01_default-agent-tools/spec.md#L126). No current read path addresses files under a user skill root outside the workspace ([tool definitions](../../src/tools.rs#L589), [host root](../../src/tools.rs#L1088)).

Kiki's Arena keeps Python values across turns. A host function's return value stays in that arena unless the model prints or inspects it; model feedback includes stdout, the final expression, and errors ([system prompt](../../prompts/system.md#L3), [feedback formatter](../../src/agent.rs#L1325)). The existing prompt treats all host outputs as untrusted and says not to follow instructions found there ([untrusted-output rule](../../prompts/system.md#L35)). This rule has no skill exception today ([system prompt](../../prompts/system.md#L1)).

Session history persists completed Python code and execution feedback, and compaction replaces older projected history with a summary and retained tail ([session records](../../src/session.rs#L595), [compaction projection](../../src/session.rs#L987)). The current session metadata has model and thinking preferences but no skill manifest ([metadata](../../src/session.rs#L372)). Child runs start from a copied arena checkpoint and construct a fresh prompt from the base plus child instructions; they do not currently carry a skill catalog as a separate object ([child arena copy](../../src/arena.rs#L790), [child prompt](../../src/subagents.rs#L1318)).

## Conventions and notable decisions

- Codex and Maki both advertise metadata before showing a body; Codex uses a [developer context fragment](../../.research/codex/source/codex-rs/ext/skills/src/fragments.rs#L39), while Maki uses a [tool description](../../.research/maki/source/plugins/skill/init.lua#L132).
- Codex validates local metadata before cataloging it ([parser](../../.research/codex/source/codex-rs/skills/src/parser.rs#L43)); Maki permits missing or malformed frontmatter and skips only an empty body ([Maki parser](../../.research/maki/source/plugins/skill/skill_helpers.lua#L3), [scan](../../.research/maki/source/plugins/skill/init.lua#L23)).
- Maki rescans for each load after recording its startup catalog ([startup catalog](../../.research/maki/source/plugins/skill/init.lua#L132), [load-time discovery](../../.research/maki/source/plugins/skill/init.lua#L163)); Codex has a [cache and watcher](../../.research/codex/source/codex-rs/app-server/src/skills_watcher.rs#L112).
- Kiki's current tool model is Python inside a persistent arena, with no standalone `skill` model tool ([system prompt](../../prompts/system.md#L3), [active tools](../../src/tools.rs#L589)).
