# Research: Plan mode in the reference harnesses

## Scope

The seven source snapshots under `.research/`: Codex, Maki, Monty, Oh My Pi, OpenCode, Pi, and smolagents. This describes the checked-in implementations, not current upstream releases or a design for Kiki. Here, *plan mode* means a distinct planning phase that delays implementation or requires a deliberate switch to execution; a checklist, a planning step inside an agent loop, and a model role alone are not the same thing.

## Summary

- Codex has a conversational collaboration mode: a prompt contract and structured `<proposed_plan>` transcript item, followed by a TUI implementation choice. Its general prohibition on mutation is prompt guidance, not a separate plan-specific sandbox. `.research/codex/source/codex-rs/collaboration-mode-templates/templates/plan.md:3-39`; `.research/codex/source/codex-rs/tui/src/chatwidget/turn_runtime.rs:226-265`; `.research/codex/source/codex-rs/protocol/src/config_types.rs:777-794`.
- Maki has a Build/Plan mode with a real plan file and a dispatcher-level restriction on declared mutable paths; a successful plan-file write opens the implementation form. Shell commands and child agents do not share that same restriction. `.research/maki/source/maki-ui/src/app/mode.rs:35-108`; `.research/maki/source/maki-agent/src/agent/tool_dispatch.rs:120-131`; `.research/maki/source/maki-ui/src/app/mod.rs:1204-1209`; `.research/maki/source/maki-lua/src/api/agent.rs:790-805`.
- Oh My Pi has a session-local plan artefact, plan-specific prompt, guarded built-in file writes, explicit `xd://propose` review, and approval options that can clear or compact context. Its main tool list otherwise remains available. `.research/oh-my-pi/source/packages/coding-agent/src/prompts/system/plan-mode-active.md:1-26`; `.research/oh-my-pi/source/packages/coding-agent/src/tools/plan-mode-guard.ts:134-163`; `.research/oh-my-pi/source/packages/coding-agent/src/modes/interactive-mode.ts:3158-3200,3725-3892`.
- OpenCode's Plan is a primary agent with path-based edit permissions; an experimental flag adds a plan-file reminder and `plan_exit` approval handoff. Its Bash permission is separate from its edit restriction. `.research/opencode/source/packages/opencode/src/agent/agent.ts:119-181`; `.research/opencode/source/packages/opencode/src/session/reminders.ts:24-89`; `.research/opencode/source/packages/opencode/src/tool/plan.ts:13-74`.
- Pi core deliberately has no plan mode; an optional example extension implements tool switching, text-plan extraction, a three-way review choice, and execution tracking. `.research/pi/source/packages/coding-agent/README.md:496-506`; `.research/pi/source/packages/coding-agent/examples/extensions/plan-mode/index.ts:90-174,200-337`.
- smolagents has automatic periodic planning steps, not an interactive plan/execute mode. Its example planning callback offers review, but its cancel action is checked too late to gate the immediately following action. `.research/smolagents/source/src/smolagents/agents.py:543-570`; `.research/smolagents/source/examples/plan_customization/plan_customization.py:62-97`.
- Monty is an interpreter rather than a plan-mode harness. Its execution suspensions let a *host* implement approval, but it has no plan prompt or plan/execute state in the inspected source. `.research/monty/source/docs/snapshots.md:20-65`; `.research/monty/source/docs/host-functions.md:187-208`; `.research/monty/source/crates/monty/src/repl.rs:487-499`.

## Findings

### Codex

The TUI starts in Default and offers Plan through `/plan` (also `/plan <prompt>`) or Shift-Tab. The selected collaboration mode is attached to a user turn; core injects its developer instructions. The Plan prompt requires exploration and clarification, forbids implementing changes until a developer message ends the mode, and asks for one final `<proposed_plan>` block. `.research/codex/source/codex-rs/tui/src/chatwidget/slash_dispatch.rs:84-101,795-828`; `.research/codex/source/codex-rs/tui/src/chatwidget/input_submission.rs:343-381`; `.research/codex/source/codex-rs/core/src/session/world_state.rs:195-203`; `.research/codex/source/codex-rs/collaboration-mode-templates/templates/plan.md:3-15,19-39,94-128`.

Only Plan turns parse the tagged block into streaming `PlanDelta` events and a completed Plan item in thread history; there is no plan-file write in this flow. After a live turn containing a Plan item, the TUI offers implement in Default, start a fresh thread with the plan in its prompt, or stay in Plan. Queued inputs and other active UI prompts can suppress that offer. `.research/codex/source/codex-rs/core/src/session/turn.rs:1879-1942,2010-2035,2273-2275`; `.research/codex/source/codex-rs/protocol/src/items.rs:45-51`; `.research/codex/source/codex-rs/tui/src/chatwidget/turn_runtime.rs:199-265`; `.research/codex/source/codex-rs/tui/src/chatwidget/plan_implementation.rs:33-110`.

The mode mask contains model, reasoning and developer-instruction fields, not approval or sandbox policy; no general Plan-specific write barrier appears on this path. The `update_plan` TODO tool is a separate mechanism and explicitly rejects use in Plan mode. Automatic turns cannot silently enter Plan. `.research/codex/source/codex-rs/protocol/src/config_types.rs:777-794`; `.research/codex/source/codex-rs/tui/src/chatwidget/settings.rs:693-709`; `.research/codex/source/codex-rs/core/src/tools/handlers/plan.rs:87-99`; `.research/codex/source/codex-rs/core/src/session/turn_input.rs:58-72`.

### Maki

Tab toggles Build/Plan in the TUI. Entering Plan allocates a `.md` path under the state directory's `plans/` directory; a return to Plan can reuse that path. The mode and plan state (`None`, `Drafting`, `Ready`) are separate. SDK `permission_mode=plan` instead uses `cwd/plan.md`; ACP also exposes Plan. `.research/maki/source/maki-ui/src/app/mod.rs:997-1001`; `.research/maki/source/maki-ui/src/app/mode.rs:15-108`; `.research/maki/source/maki-storage/src/plans.rs:6-37`; `.research/maki/source/src/sdk_mode.rs:586-599`; `.research/maki/source/maki-acp/src/methods.rs:27-67`.

The system prompt permits writing only the plan path. The tool dispatcher rejects registered-tool writes to other declared `mutable_path`s before permission approval or execution, and blocks MCP tool execution in Plan. A matching plan-file write still follows ordinary permission policy, which can auto-allow the configured file tools. A successful `ToolDone` for the exact plan path marks the plan Ready and opens a form with refine, implement, and clear-context-and-implement choices; implementation switches to Build and sends a prompt pointing to the file. `.research/maki/source/maki-agent/src/prompts/plan.md:3-18`; `.research/maki/source/maki-agent/src/agent/tool_dispatch.rs:105-160,324-342`; `.research/maki/source/maki-agent/src/permissions.rs:267-356`; `.research/maki/source/maki-ui/src/app/mod.rs:1204-1209,1819-1874`; `.research/maki/source/maki-ui/src/components/plan_form.rs:33-48`.

The dispatcher guards only tools that declare `mutable_path`; Bash is governed by ordinary permission scopes, and child `task` agents are explicitly started in Build mode while sharing the parent's permission manager. The plan-file restriction therefore does not cover every possible mutation route. `.research/maki/source/maki-agent/src/agent/tool_dispatch.rs:120-160`; `.research/maki/source/plugins/bash/init.lua:261-296`; `.research/maki/source/maki-lua/src/api/agent.rs:519-540,790-805`.

### Oh My Pi

`/plan [prompt]` and Alt+Shift+P enter the interactive mode. The session records enabled state and a plan path; the agent gets hidden plan instructions requiring a `local://<slug>-plan.md` artefact and a `write xd://propose` title to request review. `local://` maps to session-local storage, not the working tree. `.research/oh-my-pi/source/packages/coding-agent/src/slash-commands/builtin-modes.ts:228-246`; `.research/oh-my-pi/source/packages/coding-agent/src/plan-mode/state.ts:1-6`; `.research/oh-my-pi/source/packages/coding-agent/src/session/agent-session.ts:5605-5643`; `.research/oh-my-pi/source/packages/coding-agent/src/prompts/system/plan-mode-active.md:1-26`; `.research/oh-my-pi/source/packages/coding-agent/src/internal-urls/local-protocol.ts:241-255,299-310`.

Plan entry preserves the current tool list and adds the built-in write tool if available. Built-in write/edit paths reject working-tree changes, deletions and renames, while allowing other session-local scratch files as well as the canonical plan. The active prompt forbids state-changing shell commands; the inspected built-in file guard is not a blanket restriction on Bash, custom tools or arbitrary external effects. Plan `task` subagents instead get an explicit, reduced research tool set. `.research/oh-my-pi/source/packages/coding-agent/src/modes/interactive-mode.ts:3158-3200`; `.research/oh-my-pi/source/packages/coding-agent/src/tools/plan-mode-guard.ts:79-112,134-163`; `.research/oh-my-pi/source/packages/coding-agent/src/tools/write.ts:1120-1150`; `.research/oh-my-pi/source/packages/coding-agent/src/task/structured-subagent.ts:159-210,245-273`.

The proposal handler resolves a plan file and opens review. Review can refine, annotate, approve for execution while retaining or clearing/compacting context, or save and quit. Approval turns off Plan, restores execution tools, stores the plan reference and sends an execution prompt directing the next agent to the file. `/plan-review` can reopen review even without a proposal call. `.research/oh-my-pi/source/packages/coding-agent/src/tools/resolve.ts:57-64,294-311`; `.research/oh-my-pi/source/packages/coding-agent/src/modes/controllers/event-controller.ts:1818-1845`; `.research/oh-my-pi/source/packages/coding-agent/src/modes/interactive-mode.ts:3725-3892,4402-4426,4480-4615`; `.research/oh-my-pi/source/packages/coding-agent/src/prompts/system/plan-mode-approved.md:1-20`.

The CLI's `--plan` sets a *model role*, not this runtime mode; `--plan-yolo` is a distinct headless flow that auto-approves its proposal. `.research/oh-my-pi/source/packages/coding-agent/src/cli/args.ts:35-41`; `.research/oh-my-pi/source/packages/coding-agent/src/main.ts:1545-1553`; `.research/oh-my-pi/source/packages/coding-agent/src/session/prewalk.ts:257-352`.

### OpenCode

The built-in `plan` is a primary agent selectable from the TUI agent picker, not a new value of the agent `mode` type. Its permission rules deny general edits and `task.general` by default, but allow editing plan files under `.opencode/plans/*.md` or the application data directory. The plan path comes from session creation time and slug and is stored in `.opencode/plans` for a VCS worktree. `.research/opencode/source/packages/opencode/src/agent/agent.ts:29-38,156-181`; `.research/opencode/source/packages/tui/src/app.tsx:678-736`; `.research/opencode/source/packages/opencode/src/session/session.ts:331-335`.

Without the experimental plan flag, Plan gets a short read-only reminder. With it, entry injects a detailed reminder about creating or revising the plan file, creating the parent directory if necessary; switching back to Build adds an execution reminder. Under that flag on CLI clients, `plan_exit` asks the user to switch to Build; approval adds a synthetic Build user message. `plan_exit` does not itself check the file or write it. `.research/opencode/source/packages/opencode/src/session/reminders.ts:24-89`; `.research/opencode/source/packages/opencode/src/tool/registry.ts:225-248`; `.research/opencode/source/packages/opencode/src/tool/plan.ts:13-74`.

Ordinary write/edit/patch tools route through `edit` permissions, which enforce the plan-file exception. Shell commands use separate `bash` permissions; Plan does not deny Bash by default, and child agents can have their own edit permissions. Thus the Plan prompt's no-mutation rule is broader than the enforced edit-path rule. `.research/opencode/source/packages/opencode/src/tool/write.ts:44-64`; `.research/opencode/source/packages/opencode/src/tool/edit.ts:98-111`; `.research/opencode/source/packages/opencode/src/tool/apply_patch.ts:200-217`; `.research/opencode/source/packages/opencode/src/agent/agent.ts:119-181`; `.research/opencode/source/packages/opencode/src/tool/shell.ts:263-285`; `.research/opencode/source/packages/opencode/test/agent/plan-mode-subagent-bypass.test.ts:29-91`.

### Pi

Pi core says it has no built-in plan mode or to-do tool. An optional first-party example extension registers `/plan`, `--plan`, and Ctrl+Alt+P. Entering removes built-in write/edit tools, keeps otherwise active tools, adds investigation tools, injects a hidden planning prompt, and gates Bash through a command allowlist. That gate does not cover arbitrary preserved custom tools. `.research/pi/source/packages/coding-agent/README.md:496-506`; `.research/pi/source/packages/coding-agent/examples/extensions/plan-mode/index.ts:53-57,90-174,200-247`; `.research/pi/source/packages/coding-agent/test/plan-mode-extension.test.ts:105-127`.

The example extracts numbered steps from an assistant `Plan:` response, shows Execute/Stay/Refine, and restores tools on Execute. It tracks execution from `[DONE:n]` markers and persists mode/todos in session custom entries; it does not create a separate plan file. A separate example TODO tool is not this extension. `.research/pi/source/packages/coding-agent/examples/extensions/plan-mode/index.ts:116-123,249-388`; `.research/pi/source/packages/coding-agent/examples/extensions/plan-mode/utils.ts:129-169`; `.research/pi/source/packages/coding-agent/examples/extensions/todo.ts:135-140`.

### smolagents

`planning_interval` produces an initial and periodic `PlanningStep` inside the ordinary agent loop, before action steps, using facts/plan prompts and recording the plan in memory. It then goes straight to the action step, without selecting an execution mode or soliciting approval. `.research/smolagents/source/src/smolagents/agents.py:283-305,543-570,639-745`; `.research/smolagents/source/src/smolagents/memory.py:154-182`.

An example registers a `PlanningStep` callback to show the plan and ask the user to approve, amend or cancel it. Cancel sets `interrupt_switch`, but the loop checks that flag before the planning step, not again before that iteration's action. The example is therefore not a reliable pre-execution approval gate. `.research/smolagents/source/examples/plan_customization/plan_customization.py:62-97`; `.research/smolagents/source/src/smolagents/agents.py:543-570,754-756`.

### Monty

There is no agent plan mode in this interpreter snapshot. `feed_start` runs supplied Python until an external function, OS call, unresolved name or future suspends execution; a host can inspect the snapshot, grant/deny a call, then resume. Monty's read-only filesystem mount and host-function restrictions are capabilities supplied by its caller, not planning and approval states. `.research/monty/source/docs/snapshots.md:20-65`; `.research/monty/source/docs/host-functions.md:187-208`; `.research/monty/source/docs/filesystem.md:12-15,38-50`; `.research/monty/source/crates/monty/src/repl.rs:161-220,487-499`.

## Conventions & notable decisions

- The *plan artefact* varies: a tagged transcript item in Codex, file paths in Maki/Oh My Pi/OpenCode, extracted assistant text plus session metadata in Pi's example, and memory steps in smolagents. `.research/codex/source/codex-rs/core/src/session/turn.rs:2010-2035`; `.research/maki/source/maki-storage/src/plans.rs:6-37`; `.research/oh-my-pi/source/packages/coding-agent/src/prompts/system/plan-mode-active.md:20-26`; `.research/opencode/source/packages/opencode/src/session/session.ts:331-335`; `.research/pi/source/packages/coding-agent/examples/extensions/plan-mode/index.ts:279-291`; `.research/smolagents/source/src/smolagents/memory.py:154-182`.
- *Tool policy* and *prompt instruction* are separate in the implementations: Codex relies on prompt wording for general mutation, Maki and OpenCode guard some write paths, Oh My Pi guards built-in file writes, and Pi's example switches tools and checks Bash patterns. None of these cited mechanisms alone proves a read-only sandbox for all possible side effects. `.research/codex/source/codex-rs/protocol/src/config_types.rs:777-794`; `.research/maki/source/maki-agent/src/agent/tool_dispatch.rs:120-160`; `.research/opencode/source/packages/opencode/src/agent/agent.ts:119-181`; `.research/oh-my-pi/source/packages/coding-agent/src/tools/plan-mode-guard.ts:134-163`; `.research/pi/source/packages/coding-agent/examples/extensions/plan-mode/index.ts:90-113,163-174`.
